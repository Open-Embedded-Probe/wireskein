## 分析の題材（今のデータで進められる、順番待ち）

- I2C の長さの規則「9n＋1」は n = 0（1 ビットのフレーム）でも合う。CI の誤確定 12 のうち 2（記録の一部の切り出し: set:tuning+crop）は、同じ速さのおとりのクロックを SCL、本物の SCL を SDA にした仮説が、1 ビットのフレームだけで確定したもの。ただし、遅い立ち上がりの I2C（odslow）の本物の仮説にも、フレームが 1 ビットの切れはしに割れて、この穴で見つかっているものがある（穴をふさぐと速い組の odslow:2500 で ok 0.873 → 0.761、残ったバスの decode は 0.87 → 1.0）。先に odslow のフレームの切り方（遅い SDA の立ち上がりが SCL の High の間に START / STOP のように見える）を直してから、穴をふさぐ。

- （1 ビット 3 サンプル未満の UART を弱めて、誤有力は全体で 93。）I2C の二項の点数を入れてから、誤有力が 125 → 156（クロストーク 0.3 で 4 → 13、6 → 13 ほか）。ほかのバスの線やおとりの上の I2C の仮説が 0.6〜0.7 になる。START / STOP の離れや bus_free で落ちないもの。誤確定は増えていない（6 → 7）。

- UART の速さの区切り（`typed.async_segments`）: ループの中で変わり目の候補 `cand` を休みのランのリストで上書きしていて、実質 1 か所目で止まる。直すと、エッジの跳ねのある baudhop で偽の変わり目でも区切り、ok が 0.542 → 0.458 に下がった（生成の baudhop は速さが 1 回しか変わらない）。直すには、ノイズに強い変わり目の検出と、2 回以上変わる生成データが要る。

- **線のグループと時間のグループ**（bench/notes/2026-11-17-lines-and-time-review.ja.md）: あるべき姿は §11 で決めた。どこまでできるかを §12 の順で測る（採るかどうかは測った後）。

- 取引が 1 つだけの I2C（`i2cbench:h417_slow/noise`、326 本）: 本命は何も主張しない（SCL の変化 8〜20）。START・9 クロック
  ずつ・STOP がそろう 1 取引を「有力」にできるか。短い記録での誤った主張とのかね合いを、生成データのノイズで測ってから。
- bench の hardness（読めないはずのデータの印）: ebdd-50m の 1 MHz の I2C を 5 MS/s に間引くと（SCL の半周期 2.5 サンプル）、
  本命は ambiguous / unknown-sync（誤りではない）なのに、印がなく「読めるはず」で数えられる（ok_readable 0.867）。I2C は
  半周期あたりのサンプルで印を付けるべきか。
- ノイズ（spike / xtalk / bounce）での誤った確定と見分けの落ち方（noise、noise-holdout）: 計画の「悪いデータで粘る」。

- 残る誤確定 6（2026-11-18、58 のデータセット）: すべて SPI の役割の付け損ね（CS）。クロストークで CS が 100 回ほど変わり、いちばん速いクロックのゲートでは疎にならない例は、疎らさをどのクロックのゲートでも数えると 1 件減るが、候補が増えて読めたバスが 6 減り、いちばん遅い例が 2〜3 倍になった（入れていない）。スパイクで選択線らしさが 0.2 ほどに落ちる例もある。
