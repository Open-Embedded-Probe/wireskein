# ノイズの扱いを 1 つの段にする計画（2026-11-22）

## 今の形

短い Run（スパイク、クロストーク、バウンス、線自身の短い Run）を除く処理が、読みの各所に散らばっている。

| 所 | 何をするか | 判断の基準 |
|---|---|---|
| survey.gated_view | 対を測る見方。クロックの周期の 1/4 より近い変化をまとめる。速いクロックは 1 サンプルのパルスを除く | views.own_short_runs（済み）、クロックは「3 つ続く短い Run の真ん中」（済み） |
| survey.despiked_relation / _despiked_select | k サンプルより短いパルスを除いた対 / 選択線の枠 | 呼ぶ側が k を決める |
| survey._debounced_clock | バウンスのあるクロックを、まとめた線で測り直す | BOUNCED_SHARE、BOUNCE_WINDOWS |
| survey.pair_relation | データ線のリンギングと 1 サンプルのパルスを、遅いクロックの所だけ除く | RING、周期 6 サンプル以上 |
| staged.glitch_views | 同期の読みの見方。幅 2、3、5 サンプルと観測した幅で除いた兄弟 | noise_runs、broken_runs、_slow_at、GLITCH_SHARE |
| staged.rebuilt_views | 壊れたクロックを格子で作り直す | REBUILD_DATA |
| staged.single_views | 非同期の線の見方。まれなスパイクを除く兄弟、バウンスのまとめ | spikes < 0.1、bounces_paired、steady < 0.7 |
| typed.sample_edge_for | どちらの辺で読むかを、バウンスとクロストークを除いて測り直す | views.own_short_runs（済み） |

## わかったこと

- 「この短い Run は線自身のものか」を線全体で 1 回決める基準は、形だけでは 1 割近く外れる（合成の記録のノイズ前と比べた:
  周期を壊すかで ノイズ→自身 136 / 自身→ノイズ 89、規則正しさで 364 / 139）。
- パルスを 1 つずつ、隣の線の辺との時間で分けるのは、合成のクロストークが必ず 1 サンプル後に入る形にしか合わない。
  実機の結合は同じサンプルか 1 つ後。bench に xtalk:L:01 を足して、どちらでも試すようにした。
- 今の版は、ずれ 1 と 0〜1 で読めた数がほぼ同じ（760 / 761）。ずれ 1 にだけ合わせてはいない。
- 同じプロセスで前に読んだものに結果が左右されていた（9b84a20 で直した）。CI の数字の小さな揺れは、これが混ざっていた。

## 目標

1. 短い Run の分類を、記録ごとに 1 回、線ごとに行う段にする（スパイク / クロストーク / バウンス / 線自身、理由つき）。
   各所はその分類を読むだけにし、閾値を段に集める。
2. 読めた数と誤りを、今より悪くしない。速さも今より遅くしない。

## 指標とデータ

- 合成の記録: ノイズを足す前と比べて、短い Run ごとの分類の正しさ（自身 / ノイズの混同行列）。tuning の組だけで調整する。
- 端から端: noise、protomix、spi-shapes、uartlike、pulse の組（xtalk:L と xtalk:L:01、spike、bounce）、LinkE の V203
  （クロックの 1 サンプルの Run が本物）、sigrok-dumps（確かめるだけ）。
- holdout（[1000:...]、set:heldout、h417_slow の stream）は合否だけを見る。

## 合否

- 分類: 合成の tuning で、自身→ノイズの取り違えを今の最良の基準（89）より減らし、ノイズ→自身は 136 以下。
- 端から端: 読めた数が減らず、誤りが増えない。どこかで悪くなった件は、理由が言えるまで入れない。
- CI の Bench で全スイートを回し、悪くなれば戻す。

## 段取り

1. 分類の段を bench の横に作り、混同行列だけで詰める（製品は変えない）。
2. 各所を 1 つずつ分類を読む形に替え、そのつど端から端で比べる（glitch_views → single_views → despiked_* の順。
   単独で比べられる所から）。
3. 閾値が段に集まったら、製品の定数として残すものと捨てるものを決める。

## 段取り 1 の途中結果（2026-11-22）

合成の tuning（tuning の xtalk:0.3、xtalk:0.3:01、spike:0.1、bounce:0.5、decimate:4、protomix の xtalk:0.3:01、spivar の
xtalk:0.3）の 1 サンプルの Run 142 万個（自身 21 万）を、ノイズ前の記録で正解を付けて数えた（数は Run の個数）。

| 決まり（ノイズとする条件） | 自身→ノイズ | ノイズ→自身 |
|---|---|---|
| 周期を壊す（views.broken_runs） | 14,931 | 567,586 |
| 隣の線の辺の 1 サンプル後 | 20,359 | 704,038 |
| 線の Run の中央値が 3 以上、または周期を壊す | 23,548 | 102,913 |
| 1 サンプルの Run が線の半分未満、または周期を壊す | 40,903 | 18,358 |

- 自身の 1 サンプルの Run は、間引いた記録（9.3 万）と、1〜2 サンプルで変わり続ける速い線（synth-mixed-12 で 6.5 万）に
  集まる。前後の Run も 1〜2 で、規則正しい。
- ノイズの多い線（bounce:0.5、クロストーク）では、線の中央値も short_share もノイズに引きずられる。ノイズに強い長さ
  （1 サンプルを除いた Run の中央値）は、間引いた速い線を取り違える（自身→ノイズ 18 万）。
- Run の個数の誤りは、少数の線に偏る。どちらの誤りが読みを悪くするかは、端から端で決める。次は、上の 2 つの決まりで
  glitch_views と single_views の見方を作り替え、端から端で比べる。
