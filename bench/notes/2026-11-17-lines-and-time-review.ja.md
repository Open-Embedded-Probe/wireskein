# 解析の組み立てを、ユースケースから考え直す（2026-11-17）

ユーザーの問い: 線のグループと時間軸のグループを、ゼロベースでどう分析させるべきか。過去の互換や作業量ではなく、
ユースケースから「どうあるべきか」を決め、そこから段の順番と層、アルゴリズム、分け方、仕様・限界・ガイドを見直す。
RVSWD → SWIO、UART、CS 2 本の SPI、きれいな記録は、そのうちの一部の例にすぎない。

進め方: 使う人と場面（§1）→ 渡される知識（§2）→ 求められる答え（§3）→ そこから決まるもの（§4）→ 線と時間の
グループ（§5）→ 段と順番（§6）→ 例で確かめる（§7）→ 限界とガイド（§8）→ アルゴリズムと分け方（§9）→ あるべき姿
（§10）→ 今との差（§11）→ どこまでできるかを測る（§12）。あるべき姿は測る前に決まる。どこまで近づけるかは測って
決め、採るかどうかは測った後に決める。

## 1. 使う人と場面

| | 場面 | 分かっていること | 問い | 欲しいもの | 制約 |
| --- | --- | --- | --- | --- | --- |
| P1 | 自分の基板のデバッグ（ファームの開発者） | 線と方式と役割。期待はおおよそ | ドライバは何を送ったか。なぜ NACK か。タイミングは足りているか | 役割どおりの復号、誤り、タイミングの測定値、コードの出来事（目印）との対応 | 対話的に、数秒で |
| P2 | 試験の自動化（CI、HIL、pytest） | すべて。期待はコード | 期待どおりか | 合否と測定値。検査できなかったものは失敗 | 毎回同じ答え、速い、黙らない |
| P3 | 立ち上げ・未知の基板・解析 | ほとんど何も（つないだ線だけ） | 何がどの線にあるか。何のデバイスか。何が起きているか | 線の組と方式と確かさ、デバイスの候補、説明できなかった所 | 誤って言い切らない |
| P4 | 現場の不具合・長い記録の見張り | 線と方式は多くの場合わかる | いつ何が起きたか。まれな異常はどこか | 時系列の出来事、異常（ロック、リセット、グリッチ、モードの変化）、統計 | 何時間分。メモリに上限。区切って読める |
| P5 | AI やスクリプトが読む | 場面による | 要点と、掘り下げる先 | 安定した構造、要約から詳細へたどれる刻み、確かさと読めなかった所 | 文脈に収まる大きさ |
| P6 | 記録の質を確かめる（取り直すべきか） | 線 | この記録で読めるか | 線ごとのサンプル不足、ノイズ、プローブの不具合、欠損 | 復号の前に、方式を知らずに |
| P7 | ほかの道具・人へ渡す | 場面による | — | きれいな線（ノイズを除いた記録）、注釈、書き出し（sigrok、VCD、CSV） | 何を除いたかの出どころ |
| P8 | 方式・デバイスの定義を足す人 | 自分の方式 | 下の層は何を渡してくれるか | 型付きの層（ビット、フレーム、語）、点数の口 | 下調べを書き直さない |
| P9 | 正解を作る・方式を比べる（測定台、データのリポジトリ） | 正解（外から） | どれだけ読めたか | 読めた割合、黙った読み落とし、範囲付きの結果 | 正解は WireSkein から取らない |
| P10 | ロジックとアナログを合わせて見る | 線 | 電圧と論理の対応、時刻の合わせ込み | 同じ時間軸 | 元のデータを書き換えない |

## 2. 渡される知識の段階

利用者が渡せる知識は、場面によって次の段階のどこかにある。

| 段階 | 渡すもの | 例 |
| --- | --- | --- |
| K0 | 何も | 未知の記録 |
| K1 | 意味のある線、要らない線 | 「D5 はつないでいない」 |
| K2 | 線の組と方式 | 「D0〜D3 は SPI」 |
| K3 | 役割 | 「D0 = CLK、D3 = CS0、D4 = CS1」 |
| K4 | 設定 | モード、ボーレート、CS の向き |
| K5 | 期待する中身と時間 | 「この段で 0x42 に 2 バイト書く」 |

**決まること: 解析は 1 つの流れで、渡された知識はその段に入り、足りない所だけを推定する。出力の形はどの段階でも
同じ。** analyze（K0〜K2）、decode（K3〜K4）、verify（K5）は、同じ流れの入口の違いにすぎない（v1 の B2: analyze の
書き出しを decode と同じ形に、と合う）。知識が多いほど推定を飛ばせるので速く、答えは確かになる。

## 3. 求められる答えの種類

| 答え | 中身 | 要る場面 |
| --- | --- | --- |
| A1 一覧 | どの線の組に、何の方式のバスがあり、どの相手（デバイス、CS、アドレス）がいるか | P3、P5、P1 |
| A2 時系列 | 時刻の順の出来事。バスをまたいで。段（起動、接続、動作）と切り替わり | P4、P1、P5 |
| A3 中身 | 復号した層（ビット → フレーム → 方式 → デバイス） | P1、P2、P3、P8 |
| A4 確かさと覆い | 主張の確かさ、線と時間のどこを説明できたか、読めなかった所、別の解釈 | すべて。P3、P9 は特に |
| A5 記録の質 | サンプル不足、ノイズ、プローブの不具合、欠損。方式を知らなくても | P6、すべての前提 |
| A6 測定 | 周波数、セットアップ・ホールド、間隔、デューティ | P1、P2 |
| A7 判定 | 期待との一致、検査できなかった項目 | P2 |
| A8 作ったもの | きれいな記録、注釈、書き出し | P7、P9、ビューア |

A4 と A5 は、ほかのどの答えにも付く（黙らない: concept の「未解釈を解釈済みとして扱わない」）。

## 4. そこから決まる「もの」

| もの | 中身 | どの答えのため |
| --- | --- | --- |
| 線 | 取った変化、線ごとの質（A5）、活動のかたまり | A5、すべての土台 |
| エピソード | いくつかの線が一緒に動く時間（線の組 × 時間）。方式を知らずに決まる | A2 の骨組み、探索の単位 |
| バス | 物理の線の組と方式（線は共有されうる） | A1 |
| 相手 | バスの上の論理の相手（CS、I2C のアドレス、CAN の ID、多点の番地）。明示の線で選ぶ相手と、中身で選ぶ相手がある | A1、A3、A7 |
| 読み（主張） | 方式 + 役割 + **時間の範囲** + 確かさ + 層。バスか相手を単位に | A3、A4 |
| 出来事 | 刻みを持つ項目（取引、誤り、モードの切り替え、目印） | A2、A7 |
| 覆い | 線 × 時間ごとに: 読んだ（どの読みが）、同じバスのほかの相手、ノイズ、静か、誰も読めなかった | A4 |
| 区間 | 時間の区切り。利用者が与えるもの（目印、窓、ファイルの区間）と、信号から決まるもの（エピソード、モードの切り替え、速さのブロック） | A2、A7、P4 |

## 5. 線のグループと時間のグループ

### 5.1 時間のグループは 2 種類ある

1. **利用者が与える区切り**（目印の段、窓、ファイルの区間）: 全部の線を同じに切る。答えを絞る「問いの範囲」で、
   解析の構造ではない。試験の段ごとの照合（P2）、ある時間の出来事（P1）。今もある（`--segment`、`--window`）。
2. **信号から決まる区切り**: 線の組ごとに違う。読みの範囲そのもの。
   - 明示: 選択線が時間を区切る（SPI の CS、イネーブル、方向の線）。
   - 暗黙: 同じ線の組の上で、方式・設定・相手が変わる（デバッガの 2 線の問い合わせ → 1 線、起動のボーレート →
     本番のボーレート、ビットバン → 周辺機能、ピンの割り当ての変更、I2C のバスの復旧）。

### 5.2 信号の区切りは、線の組ごとに要る

- A2（時系列）と A4（覆い）は、「この線のこの時間を何が説明したか」を答える。記録全体の区切りでは、独立したバスの
  一方の切り替えが、もう一方（続いている UART）を割ってしまう。
- 続く方式（UART、PWM、I2S）は、範囲が記録全体になるだけ。線の組ごとに持つ形は、続く方式を特別扱いしない。
- 速さや設定だけが変わる場合（同じ方式）は、読みは 1 つのまま、中に設定の区切りを持つ（今の UART のブロック、
  `clock_speeds`）。方式か相手が変わるときだけ、読みを分ける。

### 5.3 ただし、独立した探索にはしない

組を決めるには時間が要り、時間を決めるには組が要る。全部の組合せを試すと、偶然に合う仮説が増え、誤確定（P3 で
いちばん避けたいこと）と費用が増える。そこで:

- エピソード（方式を知らずに、共起から決まる）を探索の単位にする。
- 主な読みが残した所（覆いの「誰も読めなかった」）を、その線と時間に絞って読み直す。2 つ目の方式や相手はそこで
  見つける。
- 最良の説明は、「同じ線の同じ時間を 2 つの読みが持たない」ように詰める。共有は、同じバスの相手どうしだけ許す。

## 6. 段と順番

```text
L0 取った記録                     書き換えない
L1 線の質と下調べ                  変化、活動のかたまり、ビット時間、局所周期、線ごとの変わり目、質（A5）
                                  ← K1（要らない線）
L2 エピソード                      どの線がいつ一緒に動くか。時系列の骨組み（A2 の最初の答え）
L3 グループ                        クロック・データ・選択線の関係を、エピソードの中で測る。相手の候補（選択線が複数）
                                  ← K2（組と方式）、K3（役割）: ここを飛ばす
L4 型付きの層と読み                 ビット → フレーム → 語 → 方式。範囲はエピソード
                                  ← K4（設定）
L5 説明を詰める                    線 × 時間を重ねない最良の組。確かさと余裕
L6 残りを読み直す                   誰も読めなかった所を、その線と時間で L3 から（回数に上限）
L7 上の層と関係                    デバイス、Debug Module、コマンドと応答、モードの切り替え、時系列の出来事
L8 答えと作ったもの                 一覧、時系列、中身、覆い、質、測定、判定（← K5）、きれいな記録
```

- L1 と L2 は方式を知らずに安く、長い記録を流しながら求められる（P4）。何も復号できなくても、質（A5）と時系列の
  骨組み（A2）は返せる。
- 長い記録の区切りは、L2 のエピソードの切れ目で切る（意味の切れ目で切れば、区切って読んでも全体と同じになりやすい）。
- 知識が渡されたら、その段の推定を飛ばす。それでも、L5 の覆い（A4）と L1 の質（A5）は必ず出す。

## 7. 例で確かめる（一部）

| 例 | モデルでの扱い |
| --- | --- |
| 続く UART と、ほかのバスのモードの切り替えが同時に | UART の読みは範囲が全体のまま。切り替えは別の線の組の中だけ |
| 起動の 74880 baud → 115200 baud | 読みは 1 つ、中に速さのブロック（同じ方式の設定の変化） |
| LinkE の 2 線の問い合わせ → SWIO | 同じ線の上に範囲の違う 2 つの読み（rvswd → swio）と、関係「切り替え」。SWIO の残りから L6 で見つける |
| SPI の CS が 2 本 | バス 1 つ、相手 2 つ。読みは相手ごとに、共有の線を写して出し、`bus` で束ねる。他方の相手の時間は覆いの「ほかの相手」 |
| I2C に複数のデバイス | バス 1 つ、相手は中身（アドレス）で分かれる。今のデバイスの層 |
| CS を取っていない共有の SPI | 相手を分けられない（限界）。1 つのバスとして読み、そう知らせる |
| ノイズの多い線 | 質（A5）で知らせ、読みはその読みが使った見え方で。きれいな記録は読みごとの見え方 |
| 何時間の記録の中のまれな異常 | L1・L2 は流しながら。異常は出来事として時系列に |
| 1 回しかない短い取引 | 証拠は範囲ごとに数える。K0 では主張しないことがある。K3 なら役割どおりに読む |
| 試験の段ごとの照合 | 利用者の区切り（目印）で範囲を絞り、相手ごとに期待を書く |

## 8. 限界とガイド

- 限界（concept の範囲、protocols）: 選択線を取っていない共有のバスは、中身で分かる方式（アドレス、ID）を除いて
  相手を分けない。同じ線の上の 2 つ目の方式は、主な読みが残した所でだけ探す。短すぎる範囲は、証拠が足りず主張
  しない。サンプル不足の線は、読めない所として知らせる。
- 仕様（analysis-format）: 読みの範囲、バスと相手、覆いの区別、出来事の時系列、質、きれいな記録の形。
- ガイド（capture-test-guide、capturing）: 選択線はすべて取る。知っていることは渡す（K の段階が上がるほど速く確か）。
  相手ごとに期待を書く。モードの切り替えのある記録は、範囲付きの読みになる。

## 9. アルゴリズムと分け方への影響

- **関係はエピソードの中で測る。** 記録全体で測ると、関係のない時間とノイズの時間が混ざる。ほかの相手の転送が
  「囲まない転送」に見え、選択線らしさを下げる。生産計画 §1 の「周期でゲートした関係」と組み合わせる（ゲートは縁の
  近さ、エピソードは時間）。
- **選択線の向きは、窓が転送を 1 つずつ、すき間なく囲むかで決める。** 囲む転送の数で決めると、ほかの相手の転送が
  多いときに逆になる（§12 で、今の decode で見つかった）。
- **証拠は範囲ごとに数える。** 短い範囲の読みは確定しにくい（短い記録と同じ）。L6 の読み直しによる誤確定を抑える。
- **費用は下がる見込み。** 全部の線 × 全部の時間でなく、エピソードごとに、そこで動く線だけで仮説を作る。
- **きれいな記録は解析の出力。** ノイズの除き方は、どのクロックで読むか、どの見え方かで決まるので、前処理で線を
  書き換えない。読みのない線は取ったまま。元の記録の SHA-256、線ごとに除いた変化の数、どの見え方かを持つ。

## 10. あるべき姿（測る前に決まること）

1. 解析は 1 つの流れ。渡された知識（K0〜K5）はその段に入り、出力の形はどの段階でも同じ。
2. 読みは時間の範囲を持つ。同じ線の同じ時間を 2 つの読みが持たない。共有は同じバスの相手どうしだけ。
3. バスと相手を分ける。読みは相手ごとに出し、共有の線を写して、`bus` で束ねる（1 つの読みだけで完結する）。
4. 覆いを、線 × 時間で出す: 読んだ、ほかの相手、ノイズ、静か、誰も読めなかった。
5. 記録の質と時系列の骨組みは、方式を知らなくても出す（L1、L2）。
6. 信号の区切りは線の組ごと。利用者の区切りは問いの範囲。2 つを混ぜない。
7. 2 つ目の方式や相手は、残りから探す。全部の組合せを先に試さない。
8. きれいな記録は解析の出力。
9. 長い記録の区切りは、エピソードの切れ目で。

## 11. 今との差（事実）

- 主張は線の組に対して記録全体で 1 つ（`_engine/stack.py` の `explanations`: 線ごとに持ち主は 1 つ）。範囲がない。
- analyze と decode と verify は、入口が別の作り（decode は役割をヒントに analyze を回し、合う読みを取る）。
- 線どうしの関係は記録全体で測る（`survey.pair_relation`）。
- 時系列の出来事、覆い（線 × 時間）、エピソードはない。読めなかった所（`uninterpreted`、`reading.unread`）はある。
- 記録の質は、読みに付く形で一部ある（`noise`、`line_faults`、`undersampled`）。方式を知らない段では出さない。
- 区切りは、利用者の区切り（目印、窓、区間）、長い記録の区切り（メモリのため、静かな所）、UART の速さのブロック。

## 12. どこまでできるかを測る

段を小さく分け、測定台で数字を取る。

1. **データ**: 合成の共有 SPI（`eval/synth.py` の `spimulti`、`spimultimix`: CS 2〜3 本、転送が交互。スイート
   `spi-multi`）。V003 の `runs/attach2`（2 線の問い合わせ → SWIO の実機。wireskein-captures）。合成の起動の
   ボーレートの切り替え、ビットバン → 周辺機能、長い記録の中のまれな異常（作る）。
2. **指標**: 相手ごとに読めた割合、範囲の端の誤差、覆いの正しさ（とくに黙った読み落とし）、誤確定、時間とメモリ。
3. **今の基準**（2026-11-17、`spimulti` の 30 例、相手 73）:
   - analyze: 30 例すべてで、CS のない SPI を 1 つ確定し、CS の線は UART の拮抗。相手ごとの読みは 0。
   - decode（役割を与える）: 全部を読めた相手は 73 のうち 20。原因は CS の向きの取り違え（§9）。ほかの相手の時間は
     すべて「読めなかった所」（313 か所）に数え、CS の線が「止まった」と知らせる。
   - (a) の後（同じ日）: 役割を与えた decode は 73 の相手すべてを読み、未解釈は 0（調整に使っていない種 1000〜 の 40 例・相手 100、UART・I2C と混ざる `spimultimix` の 80 例・相手 154 でも同じ）。直したのは 4 つ: spec のバスをそのまま組として試す（ピンごとのヒントでは CS が 1 本しか残らなかった）、選択線の向き（§9）、ほかの相手が読んだ所を `shared` に、spec の `bit_order`。analyze はまだ相手を分けない（段 (f)）。
   - 仕様が許す SPI の形（`spivar`、10 の形を種ごとに順に。スイート `spi-shapes`）、60 例（同じ日）:
     - 前から読めた: CS あり、なし、active high、GND 固定 1 本・2 本（**一度も動かない線は CS にしない**: 選ぶ証拠がない）、クロックのない選択、全体を囲む 1 つの選択（**CS を省いてよい**: 前後に 1 回ずつ変わった線と見分けられない。正解に `cs_optional`）。
     - 直して読めた: いくつもの転送を囲む選択（セッション）0 → 6/6、2〜3 相手 0 → 14/15（`staged.shared_buses`: 重ならない選択が合わせて 95 % を囲むなら 1 つのバス。囲む割合の小さい CS も、同じバーストを囲まない選択線どうしで合わせて 90 % なら候補に。足し算で決めると、ほかのバスの線まで数えて、I2C のクロックに PWM のおとりが付いた）。 セッションは、選択の 8 割以上が転送を持つときだけ（たまたま転送の周りに Low の窓が来た PWM を CS にしない）。
