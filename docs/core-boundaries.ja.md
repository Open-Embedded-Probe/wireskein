# WireSkein — コアの役割と境界（たたき台）

状態: **共通概念を検討するための案**。三つの役割で整理するが、内部実装を三層に固定する意味ではない。「シーン」「ソース」などの名称も仮である。

## 全体像

```text
プロジェクト: データ、設定、来歴をまとめて保存・持ち運ぶ単位

入力データ                 分析の定義と実行                 結果の利用
取得した記録・縮小版の記録 → 対象選択・フィルター・復号の連鎖 → 表示・保存・出力
                                                            ↓
                                              外部スクリプトなどの後工程
```

この区分は「何を保存するか」「何を再計算できるか」「何を GUI と CLI で共有するか」を話すために使う。デジタル波形、アナログ波形、低頻度の測定値、通信ログにも同じ問いを適用する。

## 1. 入力データ: 観測したもの

取得・取り込みした記録には、波形、測定値、マーカー、機器の通信ログなどがある。長い記録から切り出した区間や、ダウンサンプリングした縮小版を保管する場合は、元記録との関係と失った情報を残す。

復号したコマンド列などを、WireSkein 内で新たな入力として登録して別の分析を始めることは、現在の中心ユースケースにはない。元記録を除いて軽い結果だけを保管することはあり得るが、その場合に波形からの再復号ができなくなる点は明示する。

## 2. 分析の定義: 何をどう処理するか

どのデータ、区間、チャンネルを使うか、ソース間をどう位置合わせするか、どのフィルター・復号・集計をどの条件で適用するかを保存する。UART のフレームから上位プロトコルのコマンドへ進む処理は、この連鎖の中で扱う。前段の条件を変えたら、影響を受ける後段の結果も同じ連鎖で再計算する。これまで「シーン」と仮称していた試行単位は、この定義と結果の選択を残す候補である。複製して条件を変えれば、試行錯誤を残せる。

共通の設定をプロジェクトに置くか、試行単位で上書きするかは [プロジェクトの概念案](project-model.ja.md) で検討中である。実行して得た結果と、その結果を作った定義は区別する。結果の一時キャッシュを消しても、必要な入力と処理が残れば再計算できることを目指す。

## 3. 結果の利用: 何を見せ、何を渡すか

分析結果には、通信フレーム、コマンド、候補と不一致、測定値と条件の対応、概況などがある。結果から目的に合う行や区間を絞る操作と、各行の出力項目を選ぶ操作を分ける。GUI の表示、CLI の出力、後工程へ渡すファイルは、同じ結果から異なる内容を選べる。

例えば後工程で正常時との差分を取るために、コマンドの順序・方向・内容だけを出し、時刻や毎回変わる CRC を省く。一方、通信の遅延や CRC エラーを調べる出力では、それらを残す。どの項目を省いたかを条件として残し、元記録を保持している範囲では詳しい結果へ戻れるようにする。軽い結果だけをプロジェクトに保存する場合も、後工程に渡す出力とその来歴として扱う。

GUI の「ビュー」は画面の表示方法を指す可能性がある。保存する分析の定義、結果の選択、画面の配置が一つの単位か別々かは今後決める。

## 境界を確かめる例

| 場面 | 保存する入力の候補 | 分析の定義 | 結果の利用 |
| --- | --- | --- | --- |
| 通信を正常時と比較 | 元波形、または機器の通信ログ | チャンネル、フィルター、復号の連鎖 | 時刻・CRC を省いたコマンド列を出力し、後工程で差分を取る |
| 未知の通信を調べ直す | 元波形と、既に読めた区間の結果 | 候補、ノイズ判定、対象区間 | 未解釈区間と根拠を出し、プラグインを改善して再実行する |
| 低速の特性測定を再集計 | 測定値、設定マーカー、必要なら元のアナログ波形 | 時間合わせ、区間、条件と値の対応付け | 条件別の値をスクリプトへ渡す |

## 次に確認する境界

1. どの軽い結果をプロジェクトに保存し、元記録を除いた場合に再現できなくなる範囲をどう示すか。
2. 分析の定義と、結果から行・項目を選ぶ定義を同じ試行単位に含めるか。
3. 元記録を除いた後、どの結果を保持し、再現できる範囲をどう示すか。
4. プロジェクトの共通設定、試行ごとの設定、GUI 固有の表示設定をどう分けるか。
