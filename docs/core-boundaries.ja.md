# WireSkein — コアの役割と境界（たたき台）

状態: **共通概念を検討するための案**。三つの役割で整理するが、内部実装を三層に固定する意味ではない。「シーン」「ソース」などの名称も仮である。

## 全体像

```text
プロジェクト: データ、設定、来歴をまとめて保存・持ち運ぶ単位

入力データ                 分析の定義と実行                 結果の利用
元・合成ソースとマーカー区間 → 処理と対象の指定・フィルター・復号 → 結果と実データの出力
                                                            ↓
                                              外部スクリプトなどの後工程
```

この区分は「何を保存するか」「何を再計算できるか」「何を GUI と CLI で共有するか」を話すために使う。デジタル波形、アナログ波形、低頻度の測定値、通信ログにも同じ問いを適用する。

## 1. 入力データ: 観測したもの

取得・取り込みした記録には、波形、測定値、マーカー、機器の通信ログなどがある。複数の記録を時間上で合わせた合成ソースと、マーカーで区切られた子区間も、名前で指定できる入力として扱う。子区間は元記録の一部を指し、親全体も指定できる。合成時の時間合わせは合成側の責務とする。物理的に切り出した記録や縮小版を保管する場合は、元記録との関係と失った情報を残す。

復号したコマンド列などを、WireSkein 内で新たな入力として登録して別の分析を始めることは、現在の中心ユースケースにはない。元記録を除いて軽い結果だけを保管することはあり得るが、その場合に波形からの再復号ができなくなる点は明示する。

## 2. 分析の定義: 何をどう処理するか

利用者や外部ツールが処理ファンクションとソース名または子区間のパスを指定する。処理は入力を用意し、フィルター、復号、集計、出力などの設定付きタスクを順に実行する形をまず想定する。フィルターには条件を、出力には形式やファイル名などを設定できるようにしたい。UART のフレームから上位プロトコルのコマンドへ進む処理は、この連鎖の中で扱う。前段の条件を変えたら、影響を受ける後段の結果も同じ連鎖で再計算する。加工後のデータと分析結果の両方を使えるようにしたい。自動判定も指定して実行する処理の一つであり、ソース追加だけでコアが処理を選ぶ前提は置かない。「シーン」と仮称していた試行単位に処理の定義と実行結果をどう収めるかは未定である。

共通の設定をプロジェクトに置くか、試行単位で上書きするかは [プロジェクトの概念案](project-model.ja.md) で検討中である。実行して得た結果と、その結果を作った定義は区別する。結果の一時キャッシュを消しても、必要な入力と処理が残れば再計算できることを目指す。

## 3. 結果の利用: 何を見せ、何を渡すか

分析結果には、通信フレーム、コマンド、候補と不一致、測定値と条件の対応、概況などがある。対象区間の実データもエビデンスとして取り出せるようにしたい。一回の処理で簡易レポート、詳細レポート、実データなど複数の成果物を作る使い方がある。結果から目的に合う行や区間を絞る操作と、各行の出力項目を選ぶ操作を分ける。ファイルへの出力を主な使い方として考え、短い結果のコンソール出力も候補に残す。どの成果物を作ってどれを先に読むかは固定しない。

例えば後工程で正常時との差分を取るために、コマンドの順序・方向・内容だけを出し、時刻や毎回変わる CRC を省く。一方、通信の遅延や CRC エラーを調べる出力では、それらを残す。どの項目を省いたかを条件として残し、元記録を保持している範囲では詳しい結果へ戻れるようにする。軽い結果だけをプロジェクトに保存する場合も、後工程に渡す出力とその来歴として扱う。

GUI の「ビュー」は画面の表示方法を指す可能性がある。保存する分析の定義、結果の選択、画面の配置が一つの単位か別々かは今後決める。

## 境界を確かめる例

| 場面 | 保存する入力の候補 | 分析の定義 | 結果の利用 |
| --- | --- | --- | --- |
| 通信を正常時と比較 | 元波形、または機器の通信ログ | チャンネル、フィルター、復号の連鎖 | 時刻・CRC を省いたコマンド列を出力し、後工程で差分を取る |
| 未知の通信を調べ直す | 元波形とマーカー子区間 | 候補、ノイズ判定、対象区間 | 未解釈区間と根拠を出し、プラグインを改善して再実行する |
| 低速の特性測定を再集計 | 測定値、設定マーカー、必要なら元のアナログ波形を合わせたソース | 指定区間、条件と値の対応付け | 条件別の値をスクリプトへ渡す |

## 次に確認する境界

1. どの軽い結果をプロジェクトに保存し、元記録を除いた場合に再現できなくなる範囲をどう示すか。
2. 分析の定義と、結果から行・項目を選ぶ定義を同じ試行単位に含めるか。
3. 実データのエビデンスで結果を再現する条件と、元記録を除いた後に再分析できる範囲をどう示すか。
4. プロジェクトの共通設定、試行ごとの設定、GUI 固有の表示設定をどう分けるか。
5. 直列のタスクで足りるか、途中の分岐や複数の出力点が必要か。
