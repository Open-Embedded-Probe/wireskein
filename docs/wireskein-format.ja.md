# WireSkein のファイル形式 `.wireskein`（`wireskein/1`）

作成 2026-09-30、改訂 2026-09-30（拡張子を `.wsc` から `.wireskein` に変え、キャプチャ以外も入れられる入れ物にした。凍結の前の決定で `wireskein/1` にした: [凍結の前に決めること](freeze-review.ja.md)）。WireSkein のファイルの仕様です。読み書きの実装は `wireskein.wsc` にあり、Python の標準ライブラリだけで動きます。形式を選んだ経緯は、[ファイル形式の検討](file-formats.ja.md)にあります。

この文書で「しなければならない」と書いたものは、読み手と書き手の両方が守る規則です。

## 1. 考え方

- **WireSkein のものは、1 つの形式の入れ物に入れる。** 波形（キャプチャ）、添付、メモを入れます。将来は、マーカー、復号の結果、照合の結果も入れます。1 つのファイルを渡せば、波形と所見がそろいます。
- **拡張子ではなく、中身で見分ける。** 拡張子は `.wireskein` にします。ただし読み手は、拡張子を判断に使いません（§2.3）。
- **各チャンネルを、自分のサンプルレートのまま持つ。** 帯域に収めるために一部のチャンネルを間引くプローブは、取ったサンプルだけを保存します。間を埋める水増しはしません。
- **時間の基準は、キャプチャで 1 つの刻み（tick）。** チャンネルは「刻みいくつごとに 1 サンプルか」（`step`）と「最初のサンプルの刻み」（`phase`）を持ちます。
- **チャンネル数に上限はない。** チャンネルごとに別の項目で持つからです。
- **種類の違うチャンネルが共存できる。** ロジックとアナログを同じファイルに入れても、ロジックだけを読む読み手はロジックを読めます（§3.2）。
- **知らない部分は壊さない。** 読み手は知らない部分を無視し、書き直すときは持ち越します（§2.2）。

## 2. 入れ物

zip ファイルです。拡張子は `.wireskein` にします。中身は次のとおりです。

| 項目 | 必須 | 中身 |
| --- | --- | --- |
| `wireskein.json` | 必須 | 形式の名前（§2.1） |
| `capture.json` | キャプチャを持つとき | 刻み、チャンネルの一覧、キャプチャのメタ情報（§3） |
| チャンネルのデータ（例 `ch/0.bits`） | チャンネルごと | `capture.json` のチャンネルの `file` が指す項目（§4） |
| `attach/<名前>` | 任意 | 自由な添付（§5） |
| `notes/<番号>.json` | 任意 | 追記専用のメモ（§5） |
| `markers/markers.json` | 任意 | マーカー（§5.2） |
| `decode/annotations.json` | 任意 | 復号の注釈（§5.3） |
| `verify/`、`view/` | — | 予約（§2.4） |

- 圧縮は、zip の deflate か stored です。書き手は、`wireskein.json` を stored、ほかを deflate にします。
- 今の版の書き手は、必ずキャプチャ（`capture.json`）を入れます。読み手は、`capture.json` のないファイルを「キャプチャを含まない」ものとして扱います（波形を要る操作は、そう伝えて断ります）。

### 2.1 `wireskein.json`

UTF-8 の JSON のオブジェクトです。

| キー | 型 | 意味 |
| --- | --- | --- |
| `format` | 文字列 | `"wireskein/1"`。読み手は、知らない値のファイルを読んではなりません |

- 書き手は、`wireskein.json` を zip の**最初の項目**にし、圧縮せず（stored）に置きます。すると、ファイルの先頭の固定の位置（30 バイト目から）に `wireskein.json` の名前が現れ、zip を展開しなくても見分けられます（ODF や EPUB の `mimetype` と同じ工夫）。
- 読み手は、この位置を頼りにしてはなりません（ほかの道具で詰め直した zip では、順番が変わりえます）。見分けるのは §2.3 の手順です。

### 2.2 知らない項目

- 読み手は、この仕様にない項目を無視しなければなりません（将来の追加のため）。
- ファイルを書き直す操作（添付の置き換えなど）は、知らない項目を**そのまま持ち越さなければなりません**。
- sigrok の `.sr` への変換も、知らない項目を同じ名前で `.sr` に入れ、読み戻したときに持ち越します（§6）。`.sr` の項目と名前がぶつかるときは、断ります。
- キャプチャの中の知らない `encoding` のチャンネルは別です。データの本体なので、書き直しは断ります（§3.2）。

### 2.3 見分け方

読み手は、拡張子ではなく中身で形式を判断します。

1. zip で、`wireskein.json` を持ち、その `format` が `"wireskein/"` で始まる: WireSkein のファイルです。`format` を知らなければ、「新しい版のファイル」と伝えて断ります。
2. zip で、`version` と `metadata` を持つ: sigrok の `.sr` です（§6）。
3. どちらでもない: 読めないファイルとして断ります。

書き手は、出力の形式を拡張子で選びます（`.sr` なら sigrok、そのほかは WireSkein）。

### 2.4 決まった部分と予約した部分

| 名前 | 状態 | 中身 |
| --- | --- | --- |
| `markers/markers.json` | 定義（§5.2） | 時刻のマーカーと区間 |
| `decode/annotations.json` | 定義（§5.3） | 復号の結果を、表示のための行と区間にしたもの |
| `verify/` | 予約 | 照合の結果（期待と実際、合否） |
| `view/` | 予約 | ビューアの表示の状態 |

- 予約した名前は、定義するときに中身を決めます。書き手は、定義前にこれらの名前を使ってはなりません。
- 新しい部分を定義しても、`format` は変えません（古い読み手は、§2.2 のとおり無視して持ち越します）。
- `markers/` と `decode/` の中の、この表にない名前も予約です。

## 3. `capture.json`

UTF-8 の JSON のオブジェクトです。

形式の名前は、`wireskein.json` が持ちます（§2.1）。

| キー | 型 | 意味 |
| --- | --- | --- |
| `id` | 文字列 | このキャプチャの ID。取ったときに書き手が作る 128 ビットの乱数を、小文字の 16 進 32 文字で書いたもの。形式の変換（`.sr`、VCD との往復も）で持ち越します。ほかのファイルからこのキャプチャを指すのに使います（§5.1.1） |
| `tick_hz` | [整数, 整数] | 刻みの周波数を、分子と分母で表したもの（例 `[160000000, 3]`）。分母は 1 以上 |
| `ticks` | 整数 | キャプチャの長さ（刻みの数）。全チャンネルの終わりの最大。ロジックは `phase + n × step`、アナログは `t0_ticks + n × tick_hz / rate_hz` の切り上げ |
| `channels` | 配列 | チャンネルの一覧（下の表）。順番に意味はありません（表示の既定の順） |
| `meta` | オブジェクト | キャプチャについての小さな事実（§3.3） |

- 分数（`tick_hz`、`rate_hz`、`t0_ticks`）の分子と分母は、絶対値が 2⁵³ − 1 以下の整数です（JavaScript の数で正確に扱える範囲）。書き手が浮動小数点から分数を作るときは、分母を 10⁹ 以下にします。

`channels` の各要素:

| キー | 型 | 意味 |
| --- | --- | --- |
| `name` | 文字列 | チャンネルの名前（例 `PA5`）。ファイルの中で重複してはなりません |
| `file` | 文字列 | データの項目の名前（例 `ch/0.bits`） |
| `encoding` | 文字列 | データの持ち方（§4）。知らない値の扱いは §3.2 |
| `n` | 整数 | サンプルの数 |
| `step` | 整数（1 以上） | 刻みいくつごとに 1 サンプルか（`bits` では必須） |
| `phase` | 整数（0 以上） | 最初のサンプルの刻み。サンプル k は刻み `phase + k × step` にあります（`bits` では必須） |

### 3.1 `bits` 以外のチャンネルの時刻

`bits` 以外の `encoding` は、そのサンプルの時刻の表し方を自分で定めてよいです。ADC の実際のレートは、ロジックの刻みの整数倍にならないことが多いためです。アナログ（§4.2、§4.3）は、次のキーを使います。

| キー | 型 | 意味 |
| --- | --- | --- |
| `rate_hz` | [整数, 整数] | そのチャンネルのサンプルレート（分数、分母は 1 以上） |
| `t0_ticks` | [整数, 整数] | 最初のサンプルの時刻を、刻みで表したもの（分数。負でもよい） |

サンプル k の時刻は、刻みで `t0_ticks + k × tick_hz / rate_hz` です。

- `t0_ticks` は、プローブが返した推定値（トラックの開始のずれと、順番に切り替える ADC のチャンネルのずれ `skew_ns` を合わせた値）です。
- 分析で求めた合わせ込み（オフセットと時間の倍率）は、ここに書き戻さず、添付に入れます（§5、[事前調査](analog-mixed-survey.ja.md) §4.1）。

### 3.1.1 チャンネルの取得の設定（`acquisition`）

どの `encoding` のチャンネルも、任意のキー `acquisition`（オブジェクト）を持てます。そのチャンネルをどう取ったかを、分析で使うかにかかわらず残します。WireSkein が意味を決めているキーは次のとおりです。ほかのキーも自由に入れてよいです。

| キー | 意味 |
| --- | --- |
| `pin` | プローブのチャンネル番号（OEP の plan のチャンネル）。ADC のユニットや番号は、`meta.probe` のチップとこの番号から引けます |
| `attenuation_db` | ADC の減衰（ESP32 の 0 / 2.5 / 6 / 11 dB など）。これがないと、生の値の意味が決まりません |
| `reference` | ADC の基準電圧（オブジェクト）: `source`（`"vdd"`、`"internal"`、`"external"`）と `mv`（その電圧、mV）、`measured`（`true`: 実測、`false` / なし: 公称値）。基準電圧が電源の MCU（CH32V003 や CH32X035 など、3.3 V でも 5 V でも動くもの）では、これがないと生の値の意味が決まりません |
| `vrefint_raw` | 内部の基準電圧（Vrefint）を同時に測った生の値。基準電圧が電源のとき、実際の電源電圧を逆算するのに使えます |
| `vrefint_nominal_mv` | Vrefint の公称の電圧（mV。OEP v1 の校正の情報）。`vrefint_raw` と合わせて、電源電圧を逆算するのに使います |
| `start_uncertainty_ns` | そのチャンネル（トラック）の最初のサンプルの時刻の不確かさ（±ns）。複数のトラックを一緒に取ったとき、トラックごとに違います |
| `frontend` | 選ばれた入力の前段（OEP の `frontend_used` と describe の `frontend`: 番号、測れる範囲 `range_min_mv` / `range_max_mv`、減衰） |

### 3.2 知らない `encoding`

- 読み手は、知らない `encoding` のチャンネルを、**ほかの `encoding` として読んではなりません。**
- 解析のために読む読み手は、そのチャンネルを読み飛ばし、飛ばしたチャンネルの名前と `encoding` を利用者に示します。ほかのチャンネルは、そのまま使えます（ロジックとアナログが共存するファイルを、ロジックだけの読み手が読む場合）。
- ファイルを書き直す操作（形式の変換、別のファイルへの保存）は、飛ばしたチャンネルがあれば、データを失うので断らなければなりません。ファイルに項目を足すだけの操作（添付、メモ）は、飛ばしたチャンネルがあっても行えます。

### 3.3 `meta` のキー

任意のキーを入れてよいです。WireSkein が意味を決めているキーは次のとおりです。

| キー | 意味 |
| --- | --- |
| `start_ns` | 刻み 0 の時刻を、プローブの時計（起動からの ns、整数）で表したもの（OEP の区画の `start_ns`。推定値） |
| `start_uncertainty_ns` | `start_ns` の不確かさ（±ns。OEP の区画の `start_uncertainty_ns`。保証ではない目安） |
| `trigger_index` | トリガの位置: ロジックのチャンネルのサンプルの番号（OEP の区画の `trigger_index`）。トリガがないときは、キー自体を入れません。アナログのトラックのトリガの位置は、そのチャンネルの `acquisition.trigger_index`（そのチャンネルのサンプルの番号）です |
| `time_base_slipped` | `true`: プローブが、サンプルの時刻が遅れたことを知っている（OEP の区画の flags bit 2）。遅れがないときは、キー自体を入れません |
| `probe` | 取得した機器の情報（オブジェクト）。キーは任意です。WireSkein が意味を決めているのは次のものです。`model`、`firmware`（プローブ）、`chip`、`chip_revision`（取得した MCU）、`generation`（OEP v1 の取得の世代: `{"logic": n, "analog": n}`。どの開始の取得かを追うため）、`calibration`（出荷時の補正値。`scheme` に方式の名前、`raw` に生の値を、適用せずにそのまま入れる。例: ESP32 の eFuse の ADC の補正値） |

大きな情報や、後から足す情報は、`meta` ではなく添付かメモに入れます（§5）。

## 4. チャンネルのデータ（`encoding`）

### 4.1 `bits`（ロジック）

- 1 サンプル 1 ビットです。サンプル i は、バイト `floor(i / 8)` のビット `i mod 8`（ビット 0 = LSB）にあります。
- 長さは `ceil(n / 8)` バイトです。最後のバイトの、n を超えるビットは 0 にします（読み手は無視します）。
- サンプル k の値は、刻み `phase + k × step` から次のサンプルの刻みまでの間、変わらないものとして扱います。したがって、値の変化（エッジ）は、そのサンプルの刻みより前の `step` 刻みのどこかで起きています。これが、そのチャンネルの時間の分解能です。

### 4.2 `analog`（アナログ、生の値）

ADC の生の値を、損失なく持つ形です。OEP の `oep.fixture.analog` の値は、この形で保存します。

| キー | 型 | 意味 |
| --- | --- | --- |
| `width` | 8、16、32 | 1 サンプルのバイト数 × 8。符号なしの little endian の整数 |
| `value_bits` | 整数（任意） | 値の有効なビット数（例: 12 ビットの ADC なら 12）。値は 0〜2^value_bits − 1 |
| `zero` | 数（任意） | 電圧 0 に当たる生の値 |
| `scale_nv` | 数（任意） | 生の値 1 あたりの量（単位 `unit` の 10⁻⁹。電圧なら nV） |
| `unit` | 文字列（任意） | 換算した値の単位。既定は `"V"`（例: 電流のセンサーなら `"A"`） |
| `rate_hz`、`t0_ticks` | §3.1 | 必須 |

- データの長さは `n × width / 8` バイトです。
- 換算した値は `(値 − zero) × scale_nv × 10⁻⁹`（単位 `unit`）です（OEP の 1 次式）。
- **端で切れた値**: `value_bits` があるとき、値 0 と 2^value_bits − 1 は、入力がそれぞれ範囲の下端以下・上端以上だったことだけを表し、電圧ではありません（OEP capture §1.2）。ファイルは生の値のまま持ち、読み手が「≤ 下端」「≥ 上端」として扱います（照合は、それで決まらないものを未検査にする。ビューアは印を付けて示す）。電圧なら、**プローブのピンでの電圧**です（ADC の減衰は含み、プローブの外の分圧などは含みません）。外の分圧を戻した値は、分析のときに `acquisition` の情報から求めます。`zero` と `scale_nv` がなければ、電圧への換算は分かりません（生の値だけ）。
- **値は生のまま保存します。** 出荷時の補正（`meta.probe.calibration`）などの別の換算は、保存の段階で適用しません。分析のときに選びます（[事前調査](analog-mixed-survey.ja.md) §4.2）。
- サンプル k の値は、§3.1 の時刻の瞬間の値です（ロジックの `bits` のような「次のサンプルまで同じ」という意味は持ちません）。

### 4.3 `analog-f32`（アナログ、電圧）

電圧の float32（little endian）です。sigrok の `.sr` や Saleae の書き出しなど、電圧しか分からないものを持ち込むための形です。

| キー | 型 | 意味 |
| --- | --- | --- |
| `unit` | 文字列（任意） | 値の単位。既定は `"V"` |
| `rate_hz`、`t0_ticks` | §3.1 | 必須 |

- データの長さは `n × 4` バイトです。NaN は「値がない」を表します。

### 4.4 予約（まだ定義しない）

次のものは、必要になったときに `encoding` の新しい値として定義します。**`format` は変えません**（読み手は知らない `encoding` を読み飛ばすか断るので、古い読み手が新しいファイルを誤って読むことはありません。§3.2）。

- **エッジの列**（変化の少ないロジックを小さく持つ形）。

次のものも、仕様に加える予定です（2026-09-30 のメモ。まだ実装しません）。

- **パラレル出力の ADC**: 8 ビットや 12 ビットのパラレル出力の高速 ADC を、プローブのデジタルの入力（例: ESP32-P4）につないで取り、ビットをアナログの値に戻すものです。
  - ねらい: 20 Msps ほどのアナログを取れる見込みがあります。P4 はピンが多いので、ADC に 12 本ほど割り当てても、ほかにデジタルを 16 本取れます。
  - 前提: すぐ使えるパラレル出力の高速 ADC は、入力インピーダンスが 50 Ω ほどで、そのままでは実用的ではありません。前段の専用の基板が要ります。
  - ファイルの形: 戻した値は、今の `analog`（§4.2。例 `width` 16、`value_bits` 12、`rate_hz` は ADC のクロック）で持てるので、新しい `encoding` は要らない見込みです。どう取ったかは、`acquisition` に新しいキーで残します。候補は次のとおりです。
    - データのピン（D0 から順）、クロックのピンとラッチするエッジ
    - 符号の形（オフセットバイナリか 2 の補数）
    - パイプラインの遅れ（何クロック遅れて値が出るか。`t0_ticks` の補正に要る）
    - ADC の型番
  - 方針（2026-09-30）: **プローブは知らない。ビットから値に戻すのは分析側。** 理由は次のとおりです。
    - プローブは普通のロジアナとして、データのピンと CLK を取るだけにします。OEP でも sigrok でも Saleae でも、同じ基板と同じ変換が使えます。
    - 基板は、プローブが知らないうちに後から付けられます。基板の知識（ピンの並び、符号の形、遅れ、入力範囲）は基板についてくるもので、プローブに持たせると、基板を替えるたびにプローブを変えることになります。
    - プローブで値にしても、帯域は減りません（12 ビット × 20 Msps は、生のビットでも値でも 240 Mbit/s。16 ビットに詰めると増える）。
    - 生のビットがあれば、符号の形や遅れを間違えても、分析のときに直せます。
  - 基板の記述: 基板ごとの小さな記述ファイル（JSON）に、ピンの対応、クロックのピンとエッジ、符号の形、パイプラインの遅れ、入力範囲、型番を書きます。
    - 取るとき: 例えば `wireskein capture ... --parallel-adc board.json`。戻したアナログのチャンネルを入れ、記述をそのチャンネルの `acquisition` に入れます。
    - 取った後: 普通のロジックのキャプチャにも、同じ記述を当てて戻せるようにします。変換は、`wireskein` のコマンドにしても、別の小さなツールにしてもよいです（どのロジアナのキャプチャにも使えるので、独立したツールにする価値があります）。
  - クロック: 一番簡単なのは、ADC のクロックをプローブの取り込みと同期させる形です（プローブの PWM などで ADC を駆動し、同じレートで取る）。同期しないときは CLK も取り、そのエッジでデータを拾います（2 倍以上で取るので、帯域が増える）。
  - 元のビット: 既定では残さず、配線の確認のときだけ、ロジックのチャンネルとして残すオプションにします。
  - プローブ側に寄せる余地: 基板に ID の EEPROM を載せて自動で見分けたいときは、プローブが「この基板がつながっている」と記述を渡すだけにします。変換は分析側のままにします。

## 5. 添付とメモ

- **添付**（`attach/<名前>`）: 取得の設定、配線のメモ、分析の結果など、何でも入れられます（テキスト、JSON、バイナリ）。
  - 名前は、`/` で始まってはならず、`..` を含んではなりません。
  - 中身の形は、名前の拡張子で表します（例 `.json`、`.txt`、`.png`）。
  - 同じ名前の添付を置き換えるときは、ファイル全体を書き直します（zip に同じ名前の項目を 2 つ置いてはなりません）。
- **メモ**（`notes/<番号>.json`）: 追記専用の記録です。
  - 番号は 1 から始まる 4 桁の 10 進数（`0001`）で、足すごとに 1 ずつ増やします。
  - 中身は JSON のオブジェクトで、`time`（ISO 8601、時差付き）と `content`（文字列か JSON の値）を必ず持ちます。そのほかのキー（例 `kind`）は任意です。
  - 書いたメモは、書き換えても消してもなりません。
- どちらも、zip に項目を足すだけで、既存のファイルに追加できます。チャンネルのデータは書き直しません。

### 5.1 時刻の合わせ込み（`attach/alignment.json`）

プローブが返したトラックの開始時刻（`t0_ticks`）には、限界があります（開始のずれ、レートの誤差。[事前調査](analog-mixed-survey.ja.md) §4.1）。分析で求めた合わせ込みは、チャンネルのデータや `t0_ticks` を書き換えず、この添付に入れます。使うかどうかは、読み手が選べます。

UTF-8 の JSON のオブジェクトです。

| キー | 型 | 意味 |
| --- | --- | --- |
| `format` | 文字列 | `"wireskein-alignment/0"`。読み手は、知らない値のものを使ってはなりません |
| `channels` | オブジェクト | チャンネルの名前から、その補正（下の表）へ |

補正:

| キー | 型 | 意味 |
| --- | --- | --- |
| `offset_ticks` | 数 | オフセット a（刻み） |
| `scale` | 数 | 時間の倍率 b |
| `reference` | 文字列 | 基準にしたロジックのチャンネル |
| `via` | 文字列 | 基準と突き合わせたチャンネル（同じ信号を取ったもの）。補正するチャンネル自身のこともあります |
| `method` | 文字列 | 求め方（今は `"edges"`: エッジの位置の突き合わせ） |
| `matched` | 整数 | 突き合わせたエッジの数 |
| `residual_ticks` | 数 | 残りの誤差（突き合わせたエッジの二乗平均、刻み） |
| そのほか | — | 求めた条件（しきい値、探した範囲など）。任意 |

- ファイルに書いた時刻 t（刻み）の、合わせた後の時刻は `a + b × t` です。アナログのサンプル k なら、t は §3.1 の時刻です。
- 同じ ADC で取ったチャンネルは、同じトラックの時計で動くので、1 つのチャンネル（`via`）で求めた補正を、ほかのチャンネルにも同じ値で書きます。
- `channels` の補正は、同じファイルの中で、アナログのチャンネルをロジックの刻みに合わせるものです。基準はロジックで、ロジックのチャンネルは補正しません。
- 求め直したときは、添付を置き換えます（§5 の規則のとおり、ファイル全体を書き直す）。

#### 5.1.1 別のファイルへの合わせ込み（`files`）

別のプローブで同時に取ったキャプチャを、1 つの時間軸で見るためのものです。元のファイルはどちらも書き換えず、合わせる側のファイルの `alignment.json` に、基準のファイルへの対応を足します。

| キー | 型 | 意味 |
| --- | --- | --- |
| `files` | オブジェクト（任意） | 基準のファイルの名前（パスを除いた名前）から、下の表の対応へ |

対応:

| キー | 型 | 意味 |
| --- | --- | --- |
| `capture_id` | 文字列 | 基準のファイルの `capture.json` の `id`（§3）。同じ名前の別のファイルと取り違えないため |
| `offset_ticks` | 数 | a（基準のファイルの刻み） |
| `scale` | 数 | b（基準の刻み ÷ このファイルの刻み。2 つの時計のずれを含む） |
| `reference` | 文字列 | 基準のファイルの、突き合わせたロジックのチャンネル |
| `via` | 文字列 | このファイルの、同じ信号を取ったチャンネル |
| `method`、`matched`、`residual_ticks` など | — | §5.1 と同じ |

- このファイルのロジックの刻み t は、基準のファイルの刻み `a + b × t` に対応します。
- このファイルのアナログのチャンネルは、まず `channels` の補正（あれば）でこのファイルのロジックの刻みに合わせ、そのうえでこの対応を使います。
- 読み手は、`capture_id` が合わなければ、この対応を使ってはなりません（名前だけが同じ別のファイル）。`id` は形式の変換で持ち越すので、基準を `.sr` などにして戻しても、対応は使えます。

### 5.2 マーカー（`markers/markers.json`）

利用者やツールが付ける、時刻の目印と区間です。ビューアで付けたものも、ここに入れます。

UTF-8 の JSON のオブジェクトです。

| キー | 型 | 意味 |
| --- | --- | --- |
| `format` | 文字列 | `"wireskein-markers/0"`。読み手は、知らない値のものを使ってはなりません |
| `markers` | 配列 | マーカー（下の表）。順番に意味はありません |

マーカー:

| キー | 型 | 意味 |
| --- | --- | --- |
| `t` | 数 | 時刻（刻み。§3 の刻み、合わせ込みの前の値） |
| `end` | 数（任意） | 区間の終わり（刻み）。あれば `t`〜`end` の区間 |
| `label` | 文字列 | 名前 |
| `note` | 文字列（任意） | 説明 |
| `by` | 文字列（任意） | 付けたもの（`"viewer"`、ツールの名前など） |
| `time` | 文字列（任意） | 付けた日時（ISO 8601、時差付き） |

- メモ（§5）と違い、マーカーは書き換えてよいです。書き換えるときは、ファイル全体を書き直します（§5 の添付の置き換えと同じ）。

### 5.3 復号の注釈（`decode/annotations.json`）

復号の結果を、ビューアが描くための行と区間にしたものです。プロトコルごとの意味は持たず、ビューアはプロトコルを知らずに描けます。サーバーのないビューアでも、この項目があれば復号の結果を表示できます。

UTF-8 の JSON のオブジェクトです。

| キー | 型 | 意味 |
| --- | --- | --- |
| `format` | 文字列 | `"wireskein-annotations/0"`。読み手は、知らない値のものを使ってはなりません |
| `source` | 文字列（任意） | 作ったもの（例 `"wireskein 0.0.12 analyze"`） |
| `rows` | 配列 | 行（下の表） |

行:

| キー | 型 | 意味 |
| --- | --- | --- |
| `name` | 文字列 | 行の名前（例 `"i2c transactions"`） |
| `near` | 文字列（任意） | この行を下に置くチャンネルの名前 |
| `verdict`、`score` | 文字列、数（任意） | この行のもとになった判定の確かさ（例 `"confirmed"`、`"likely"` と 0〜1 の点）。ビューアは、確かでない行をそうと分かるように示します |
| `items` | 配列 | 区間: `s`（始まりの刻み）、`e`（終わりの刻み。任意、なければ点）、`text`（表示する文字列）、`level`（任意: `"ok"`、`"warn"`、`"error"`）、`detail`（任意: 元の値。JSON） |

- 刻みは §3 の刻みです。
- 復号し直したときは、項目を置き換えます。

## 6. 他の形式との関係

- **sigrok の `.sr`**: 全チャンネルで 1 つのレートです。書き出すときは、遅いチャンネルを刻みのレートに水増しします。各チャンネルの `step` と `phase`、正確な `tick_hz`、`id`、`meta` は、`.sr` の中の `wireskein/sr-extra.json`（`"format": "wireskein-sr-extra/1"`）に入れます。添付とメモと知らない項目（§2.2）も、同じ名前で `.sr` に入れます（知らない項目の名前は `wireskein/sr-extra.json` の `extras` に並べます）。sigrok は、どれも無視します。WireSkein は、これらを読み戻して、元のキャプチャを復元します。
  - 今の実装の `.sr` の書き出しは、32 チャンネルまでです。
  - **アナログ**: `.sr` のアナログは、電圧の float32 で、ロジックと同じレートです。
    - 読むときは、`analog-f32`（`rate_hz` は `.sr` のレート、`t0_ticks` は 0）にします。
    - 書くときは、サンプルの時刻が刻みにそろう（`tick_hz / rate_hz` と `t0_ticks` が整数）チャンネルだけを書き、遅いものは刻みのレートに水増しします。そろわないチャンネルがあれば、断ります。
    - `analog` は、`zero` と `scale_nv` で電圧にして書きます。これらがなければ断ります。生の値と `acquisition` は `wireskein/sr-extra.json` に入れ、読み戻したときに `analog` として復元します。
- **VCD**: 変化点だけを書くので、レートの違うチャンネルも水増しせずに書けます。
  - `$timescale` は、刻みの周期がちょうど整数倍になる最大の単位（1、10、100 × s〜fs）です。例: 20 MHz（50 ns）は 10 ns、160/3 MHz（18.75 ns）は 10 ps。
  - アナログは `real` の変数（電圧。換算がなければ生の値）で書きます。
  - 正確な刻み、各チャンネルの `step` と `phase`、`acquisition`、`id`、`meta`、アナログのレートと開始は、`$comment wireskein {...} $end` に JSON で入れます（`"format": "wireskein-vcd-extra/1"`）。ほかの道具は無視し、WireSkein は読み戻して復元します。
  - 添付とメモは VCD に入れられません。`convert` は、そう知らせます。
  - ほかの道具の VCD を読むとき:
    - 刻みは、変化の時刻の最大公約数です。
    - 1 ビットの変数はロジック、ベクタはビットごとのチャンネル（`NAME[k]`）になります。x と z は 0 として読み、その数を `meta.vcd_x_or_z` に入れます。
    - `real` は、変化の間隔が一定のとき（サンプルした信号）だけアナログとして読みます。そうでないものは読まずに名前を示します（ないサンプルを作らないため）。
  - sigrok は、`$timescale` をサンプルレートとして読みます（上の 20 MHz の例では 100 MHz。変化点の位置は同じ）。
- **記録（run）**: `wireskein.runlog` は、キャプチャを 1 つずつ `cNNNN.wireskein` として保存します（記録の形式 `wireskein-run/3`、[記録の形式](run-format.ja.md)）。記録の途中で 1 つの zip に追記し続けると、途中で落ちたときに zip の目次が書かれず、全体が読めなくなります。そのため記録はディレクトリのままにし、1 回ごとに別のファイルにします。

## 7. 版の上げ方

- 読み手が今の規則のまま読めて、意味を取り違えない追加（新しい `meta` のキー、新しい `encoding` の値、新しい部分、新しい任意の項目）では、`format` を変えません。
- それ以外の変更（既存のキーの意味や必須の項目を変える）では、`format` の番号を上げます（`wireskein/2`）。読み手は、知らない番号のファイルを読みません（§2.1）。
- 版の中の小さい番号（minor）は作りません。足す変更は、読み手が知らないものを無視する規則（§2.2、§3.2）で受けます。
- **`wireskein/1` は、凍結の候補です。** 凍結の前に決めること（[freeze-review](freeze-review.ja.md)）を入れた版で、凍結したら互換を守る最初の版にします。**まだ凍結していないので、それまでは互換のない変更がありえます。** β の間の `wireskein/0` のファイルは読みません。
