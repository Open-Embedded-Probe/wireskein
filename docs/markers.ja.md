# マーカー

長い記録や試験の記録を、実験の文脈（どのテストの、どのステップか）で区間に分けるための目印です。区間に分ける処理は `src/wireskein/_engine/markers.py`、書式（方言）の定義は `src/wireskein/decl/markers/*.toml` にあります。

## 1. 見出し型（既定の方言 `heading`）

```text
# test_pwm                 ← 階層 1: テスト
## duty=64                 ← 階層 2: ステップ（1 つの条件）
PWM 64                     ← マーカーでない行: イベント
PWM duty=64
##                         ← 名前のない同じ階層: ステップを閉じる
## duty=128
...
#                          ← テストを閉じる
```

| 規則 | 内容 |
| --- | --- |
| 階層 | 行頭の `#` の数。深さに上限はない（テスト、ステップ、フェーズの 3 段が目安） |
| 閉じ方 | 同じ階層か上の階層の次の見出しで閉じる。名前のない見出し（`##` だけ）は閉じるだけで、新しい区間を作らない |
| 区間のパス | 見出しの名前を `/` でつなぐ（例 `test_pwm/duty=64`） |
| 同じ名前 | 同じ親の下で名前が重なると、最初のものは名前のまま、2 回目から `duty=64[1]`、`duty=64[2]` と番号を付ける。元の文字列は残す |
| 親と子 | 親の区間を選ぶと、子を含む全範囲を扱う。子の見出しは、親の中のイベントとして見える |
| 壊れた構造 | 階層の飛び（`#` の次に `###`）と、対応する見出しのない閉じを「問題」として記録する。黙って直さない。閉じないまま記録が終わった区間は、記録の終わりで閉じる |

理由:

- **見出しの形にしたのは、** 人が読めて、階層を数えるだけで区間の木が決まり、Markdown と同じ直感で書けるからです。
- **2 回目から番号を付けるのは、** あとから同じ名前の区間を足しても、前の区間のパス（と、それに付けた期待）が変わらないようにするためです。
- **壊れた構造を問題として出すのは、** 構造が崩れると、キャプチャが別のステップの期待で照合されるおそれがあるからです。照合（`wireskein verify`）では NG（`markers`）になります。

## 2. マーカーでない行はイベント

マーカーの書式に合わない行（コマンド、応答、パラメータ）は、時刻付きのイベントとして区間の中に残します。区間ごとに「どのコマンドがどこで渡されたか」が分かります。イベントは主に GUI 向けで、CLI の出力には既定で含めません（`wireskein analyze --events`、`wireskein segments --events`、`wireskein verify --json ... --log`）。

## 3. マーカーの置き場所

### 3.1 PC 側のログ（試験の記録）

`wireskein.runlog.Recorder` が、見出しを PC 側のログ（`run.json`）に書きます。キャプチャは、取ったときに開いていた区間に割り当てます（[記録の形式](run-format.ja.md) §2.2）。

コマンドをデバッグ線や別の経路で送り、キャプチャがステップごとの単発で短い試験では、波形の中にマーカーを置く場所がありません。そのためマーカーは PC 側に持ち、**DUT のファームウェアは変えずに済む**形にしています。

### 3.2 波形の中（UART に流す）

長い記録では、DUT や試験の道具が UART にマーカーの行を流し、`wireskein segments` や `wireskein analyze --segment PATH` で区間に分けます。

- 区間は、マーカーの行の送信が終わった時点から、閉じる行の送信が始まる時点まで。マーカーの通信そのものは区間に入りません。
- コマンドと同じ UART にマーカーを流すときは、DUT のコマンド処理に次の規則が要ります。
  - `#` で始まる行はコメントとして捨て、応答もエコーもしない。
  - コマンドの行は `#` で始めない。

## 4. ほかの方言

既存の記録の書式は、`decl/markers/` に TOML の方言を足して読みます。行の種類は 4 つです。

| 種類 | 意味 |
| --- | --- |
| `begin` | その階層の区間を開く（同じ階層か深い区間は閉じる） |
| `end` | いちばん近い同じ階層の区間を閉じる（名前や番号を照らし合わせる）。`end` のないまま閉じた区間は問題として記録する |
| `point` | 次の同じ階層の `point` か、親の終わりまで続く区間 |
| `attr` | いちばん内側の区間にキーと値を付ける（JSON として読めれば JSON） |

例: `i2cdb`（`CASE_BEGIN` / `CASE_END` で囲み、`PHASE` を区間、`INPUT` と `RESULT` を属性にする書式）。
