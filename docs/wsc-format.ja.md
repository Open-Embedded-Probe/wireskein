# キャプチャのファイル形式 `.wsc`（`wireskein-capture/0`）

作成 2026-09-30。WireSkein のキャプチャのファイルの仕様です。読み書きの実装は `wireskein.wsc` にあり、Python の標準ライブラリだけで動きます。形式を選んだ経緯は、[ファイル形式の検討](file-formats.ja.md)にあります。

この文書で「しなければならない」と書いたものは、読み手と書き手の両方が守る規則です。

## 1. 考え方

- **各チャンネルを、自分のサンプルレートのまま持つ。** 帯域に収めるために一部のチャンネルを間引くプローブは、取ったサンプルだけを保存します。間を埋める水増しはしません。
- **時間の基準は、キャプチャで 1 つの刻み（tick）。** チャンネルは「刻みいくつごとに 1 サンプルか」（`step`）と「最初のサンプルの刻み」（`phase`）を持ちます。
- **チャンネル数に上限はない。** チャンネルごとに別のファイルで持つからです。
- **種類の違うチャンネルが共存できる。** 今定義しているのはロジック（`bits`）だけですが、アナログなどのチャンネルを同じファイルに入れても、ロジックだけを読む読み手はロジックを読めます（§3.2）。
- **キャプチャについてのほかの情報も入れられる。** 自由な添付と、追記専用のメモを持ちます。

## 2. 入れ物

zip ファイルです（拡張子は `.wsc`）。中身は次のとおりです。

| 項目 | 必須 | 中身 |
| --- | --- | --- |
| `capture.json` | 必須 | 形式、刻み、チャンネルの一覧、キャプチャのメタ情報（§3） |
| チャンネルのデータ（例 `ch/0.bits`） | 必須（チャンネルごと） | `capture.json` のチャンネルの `file` が指す項目（§4） |
| `attach/<名前>` | 任意 | 自由な添付（§5） |
| `notes/<番号>.json` | 任意 | 追記専用のメモ（§5） |

- 圧縮は、zip の deflate か stored です。書き手は deflate を使います。
- 読み手は、この表にない項目を無視しなければなりません（将来の追加のため）。

## 3. `capture.json`

UTF-8 の JSON のオブジェクトです。

| キー | 型 | 意味 |
| --- | --- | --- |
| `format` | 文字列 | `"wireskein-capture/0"`。読み手は、知らない値のファイルを読んではなりません |
| `tick_hz` | [整数, 整数] | 刻みの周波数を、分子と分母で表したもの（例 `[160000000, 3]`）。分母は 1 以上 |
| `ticks` | 整数 | キャプチャの長さ（刻みの数）。全チャンネルの終わりの最大。ロジックは `phase + n × step`、アナログは `t0_ticks + n × tick_hz / rate_hz` の切り上げ |
| `channels` | 配列 | チャンネルの一覧（下の表）。順番に意味はありません（表示の既定の順） |
| `meta` | オブジェクト | キャプチャについての小さな事実（§3.3） |

`channels` の各要素:

| キー | 型 | 意味 |
| --- | --- | --- |
| `name` | 文字列 | チャンネルの名前（例 `PA5`）。ファイルの中で重複してはなりません |
| `file` | 文字列 | データの項目の名前（例 `ch/0.bits`） |
| `encoding` | 文字列 | データの持ち方（§4）。知らない値の扱いは §3.2 |
| `n` | 整数 | サンプルの数 |
| `step` | 整数（1 以上） | 刻みいくつごとに 1 サンプルか（`bits` では必須） |
| `phase` | 整数（0 以上） | 最初のサンプルの刻み。サンプル k は刻み `phase + k × step` にあります（`bits` では必須） |

### 3.1 `bits` 以外のチャンネルの時刻

`bits` 以外の `encoding` は、そのサンプルの時刻の表し方を自分で定めてよいです。ADC の実際のレートは、ロジックの刻みの整数倍にならないことが多いためです。アナログ（§4.2、§4.3）は、次のキーを使います。

| キー | 型 | 意味 |
| --- | --- | --- |
| `rate_hz` | [整数, 整数] | そのチャンネルのサンプルレート（分数、分母は 1 以上） |
| `t0_ticks` | [整数, 整数] | 最初のサンプルの時刻を、刻みで表したもの（分数。負でもよい） |

サンプル k の時刻は、刻みで `t0_ticks + k × tick_hz / rate_hz` です。

- `t0_ticks` は、プローブが返した推定値（トラックの開始のずれと、順番に切り替える ADC のチャンネルのずれ `skew_ns` を合わせた値）です。
- 分析で求めた合わせ込み（オフセットと時間の倍率）は、ここに書き戻さず、添付に入れます（§5、[事前調査](analog-mixed-survey.ja.md) §4.1）。

### 3.1.1 チャンネルの取得の設定（`acquisition`）

どの `encoding` のチャンネルも、任意のキー `acquisition`（オブジェクト）を持てます。そのチャンネルをどう取ったかを、分析で使うかにかかわらず残します。WireSkein が意味を決めているキーは次のとおりです。ほかのキーも自由に入れてよいです。

| キー | 意味 |
| --- | --- |
| `pin` | プローブのチャンネル番号（OEP の plan のチャンネル）。ADC のユニットや番号は、`meta.probe` のチップとこの番号から引けます |
| `attenuation_db` | ADC の減衰（ESP32 の 0 / 2.5 / 6 / 11 dB など）。これがないと、生の値の意味が決まりません |

### 3.2 知らない `encoding`

- 読み手は、知らない `encoding` のチャンネルを、**ほかの `encoding` として読んではなりません。**
- 解析のために読む読み手は、そのチャンネルを読み飛ばし、飛ばしたチャンネルの名前と `encoding` を利用者に示します。ほかのチャンネルは、そのまま使えます（ロジックとアナログが共存するファイルを、ロジックだけの読み手が読む場合）。
- ファイルを書き直す操作（形式の変換、別のファイルへの保存）は、飛ばしたチャンネルがあれば、データを失うので断らなければなりません。ファイルに項目を足すだけの操作（添付、メモ）は、飛ばしたチャンネルがあっても行えます。

### 3.3 `meta` のキー

任意のキーを入れてよいです。WireSkein が意味を決めているキーは次のとおりです。

| キー | 意味 |
| --- | --- |
| `start_us` | 刻み 0 の時刻を、プローブの時計（µs、整数）で表したもの（OEP の区画の `start_us`） |
| `time_base_slipped` | `true`: プローブが、サンプルの時刻が遅れたことを知っている（OEP の区画の flags bit 2）。遅れがないときは、キー自体を入れません |
| `probe` | 取得した機器の情報（オブジェクト）。キーは任意です。WireSkein が意味を決めているのは次のものです。`model`、`firmware`（プローブ）、`chip`、`chip_revision`（取得した MCU）、`calibration`（出荷時の補正値。`scheme` に方式の名前、`raw` に生の値を、適用せずにそのまま入れる。例: ESP32 の eFuse の ADC の補正値） |

大きな情報や、後から足す情報は、`meta` ではなく添付かメモに入れます（§5）。

## 4. チャンネルのデータ（`encoding`）

### 4.1 `bits`（ロジック）

- 1 サンプル 1 ビットです。サンプル i は、バイト `floor(i / 8)` のビット `i mod 8`（ビット 0 = LSB）にあります。
- 長さは `ceil(n / 8)` バイトです。最後のバイトの、n を超えるビットは 0 にします（読み手は無視します）。
- サンプル k の値は、刻み `phase + k × step` から次のサンプルの刻みまでの間、変わらないものとして扱います。したがって、値の変化（エッジ）は、そのサンプルの刻みより前の `step` 刻みのどこかで起きています。これが、そのチャンネルの時間の分解能です。

### 4.2 `analog`（アナログ、生の値）

ADC の生の値を、損失なく持つ形です。OEP の `oep.fixture.analog` の値は、この形で保存します。

| キー | 型 | 意味 |
| --- | --- | --- |
| `width` | 8、16、32 | 1 サンプルのバイト数 × 8。符号なしの little endian の整数 |
| `value_bits` | 整数（任意） | 値の有効なビット数（例: 12 ビットの ADC なら 12）。値は 0〜2^value_bits − 1 |
| `zero` | 数（任意） | 電圧 0 に当たる生の値 |
| `scale_nv` | 数（任意） | 生の値 1 あたりの電圧（nV） |
| `rate_hz`、`t0_ticks` | §3.1 | 必須 |

- データの長さは `n × width / 8` バイトです。
- 電圧は `(値 − zero) × scale_nv × 10⁻⁹` V です（OEP の 1 次式）。`zero` と `scale_nv` がなければ、電圧への換算は分かりません（生の値だけ）。
- **値は生のまま保存します。** 出荷時の補正（`meta.probe.calibration`）などの別の換算は、保存の段階で適用しません。分析のときに選びます（[事前調査](analog-mixed-survey.ja.md) §4.2）。
- サンプル k の値は、§3.1 の時刻の瞬間の値です（ロジックの `bits` のような「次のサンプルまで同じ」という意味は持ちません）。

### 4.3 `analog-f32`（アナログ、電圧）

電圧の float32（little endian）です。sigrok の `.sr` や Saleae の書き出しなど、電圧しか分からないものを持ち込むための形です。

| キー | 型 | 意味 |
| --- | --- | --- |
| `unit` | 文字列（任意） | 値の単位。既定は `"V"` |
| `rate_hz`、`t0_ticks` | §3.1 | 必須 |

- データの長さは `n × 4` バイトです。NaN は「値がない」を表します。

### 4.4 予約（まだ定義しない）

次のものは、必要になったときに `encoding` の新しい値として定義します。**`format` は変えません**（読み手は知らない `encoding` を読み飛ばすか断るので、古い読み手が新しいファイルを誤って読むことはありません。§3.2）。

- **エッジの列**（変化の少ないロジックを小さく持つ形）。

## 5. 添付とメモ

- **添付**（`attach/<名前>`）: 取得の設定、配線のメモ、分析の結果など、何でも入れられます（テキスト、JSON、バイナリ）。
  - 名前は、`/` で始まってはならず、`..` を含んではなりません。
  - 中身の形は、名前の拡張子で表します（例 `.json`、`.txt`、`.png`）。
  - 同じ名前の添付を置き換えるときは、ファイル全体を書き直します（zip に同じ名前の項目を 2 つ置いてはなりません）。
- **メモ**（`notes/<番号>.json`）: 追記専用の記録です。
  - 番号は 1 から始まる 4 桁の 10 進数（`0001`）で、足すごとに 1 ずつ増やします。
  - 中身は JSON のオブジェクトで、`time`（ISO 8601、時差付き）と `content`（文字列か JSON の値）を必ず持ちます。そのほかのキー（例 `kind`）は任意です。
  - 書いたメモは、書き換えても消してもなりません。
- どちらも、zip に項目を足すだけで、既存のファイルに追加できます。チャンネルのデータは書き直しません。

## 6. 他の形式との関係

- **sigrok の `.sr`**: 全チャンネルで 1 つのレートです。書き出すときは、遅いチャンネルを刻みのレートに水増しします。各チャンネルの `step` と `phase`、正確な `tick_hz`、`meta` は、`.sr` の中の `wireskein.json` に入れます。添付とメモも、同じ名前で `.sr` に入れます。sigrok は、どれも無視します。WireSkein は、これらを読み戻して `.wsc` を復元します。
  - 今の実装の `.sr` の書き出しは、32 チャンネルまでです。
  - **アナログ**: `.sr` のアナログは、電圧の float32 で、ロジックと同じレートです。
    - 読むときは、`analog-f32`（`rate_hz` は `.sr` のレート、`t0_ticks` は 0）にします。
    - 書くときは、サンプルの時刻が刻みにそろう（`tick_hz / rate_hz` と `t0_ticks` が整数）チャンネルだけを書き、遅いものは刻みのレートに水増しします。そろわないチャンネルがあれば、断ります。
    - `analog` は、`zero` と `scale_nv` で電圧にして書きます。これらがなければ断ります。生の値と `acquisition` は `wireskein.json` に入れ、読み戻したときに `analog` として復元します。
- **記録（run）**: `wireskein.runlog` は、キャプチャを 1 つずつ `cNNNN.wsc` として保存します（記録の形式 `wireskein-run/1`）。

## 7. 版の上げ方

- 読み手が今の規則のまま読めて、意味を取り違えない追加（新しい `meta` のキー、新しい `encoding` の値、新しい任意の項目）では、`format` を変えません。
- それ以外の変更（既存のキーの意味や必須の項目を変える）では、`format` を `wireskein-capture/1` に上げます。
