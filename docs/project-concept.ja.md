# WireSkein — プロジェクトの目的と範囲

状態: **最上流の構想案**。「データを入力し、分析し、後続の分析に使える結果を出力する」ことを製品の核とする方向は確認済み。その他の範囲や優先順位、機能の詳細、データの表現、同期方法、実装方法は引き続き検討する。

## 背景

電子機器の開発や実験では、ロジックアナライザのデジタル信号、アナログ波形、計測器の値、シリアル出力、機器の設定、操作ログなどが別々の道具に記録される。個々の道具ではデータを確認できても、「何が起き、その前後に別の記録では何が起きたか」を調べるには、形式の変換、時刻の照合、手作業での転記が必要になりやすい。既存の道具もデジタル信号とアナログ波形、速い変化と遅い変化のどちらかに得意分野が偏りがちである。

ロジックアナライザの解析でも、利用者が通信方式や条件を先に指定しなければ調査を始めにくい。新しい取得機器や独自の解析を加える手順が複雑だと、試したり使い続けたりする負担が大きい。機器や用途ごとに別の道具へ分かれると、共通の記録や分析の体験を保ちにくい。

独自のスクリプトで記録を調べる場合も、形式の読み込み、エッジやパルスの抽出、周期の測定、ノイズを考慮した区間分けといった共通の下調べが繰り返される。これらの結果を後工程へ渡しにくいと、固有の問いに答える前に同じ作業をやり直すことになる。

長時間の実験では、すべての記録を同じ細かさで眺めることも難しい。信号や測定値の変化、通信内容、利用者が付けたラベルを手掛かりに、注目する区間へ進み、その根拠となる記録へ戻れることが求められる。条件ごとに独立した実験と、全体を通して追う連続的な実験では、同じ長い記録でも適した分析範囲が異なる。

## 目的

WireSkein の核は、データを受け取り、共通的な下調べから意味のある内容の解釈までを行い、その結果を後続の分析や外部での利用に使える形で出力することである。入力は特定の機器、記録形式、データの種類に限定しない。分析結果も、新しい分析の入力として扱えることを目指す。

WireSkein の出力そのものが最終的な答えになるとは限らない。自動テストに伴う記録を処理した後も、独自スクリプト、別の分析ツール、人による調査、AI を使った分析などが続くことを前提とする。そのため、分析結果は画面表示だけでなく、後工程が扱いやすいデータとして取り出せる必要がある。既知の通信ではコマンドや応答を主な結果とし、信号の特徴は必要なときに調べられる形が望ましい。

データの取得・記録は、この核に入力を渡すための重要な利用形態である。利用者は記録した現象を見つけ、解釈し、別の記録と照合し、後から調べ直せる。実験の進行そのものは製品の中心に置かない。

利用者が既知の条件や実験の文脈を与えられる一方で、アプリもデータから変化や構造を見つけ、あり得る解釈を根拠とともに示せるようにしたい。記録を取得した時点で分析方法を決め切る必要はなく、後から別の視点で調べられることを重視する。

出発点にはロジックアナライザの記録の分析がある。製品の対象はデジタル信号に限らず、アナログ波形、間欠的な測定値、文字列、イベントなども含む。特定の取得機器や記録形式を、この目的の前提にはしない。公開・配布には MIT ライセンスを想定する。

## 中心となる利用体験

利用者は、ライブ取得したデータ、既存の記録、以前の分析結果などを入力する。用途に応じて、コマンドと応答の時系列、通信の候補、周波数が変わる区間、未解釈の信号、エッジやパルスなどを確認し、保存・出力して次の分析へ渡す。結果が元のデータのどこから、どの条件で得られたかをたどれることを目指す。

未解釈の箇所は、位置と観測できた特徴を残す。利用者が解析機能を改善した後、同じ記録の該当箇所を再分析し、新しく分かった内容を得られることを目指す。

情報量を抑える際には、既知の内容をコマンドや応答として整理しながら、未解釈の信号、誤り、条件が変わった場所を隠さない。詳細を主な出力に載せない場合も、再分析に必要な元の記録との関係を保つ。元の記録を保存しない運用で何が再分析できなくなるかは、別途明確にする。

複数の記録を一つの調査または実験に関係するものとして並べて見ることもできる。データ源ごとに時刻の精度や開始位置が異なる場合は、必要に応じて対応関係を調整できる。必要な精度は、通信波形を照合する場合と、数分間隔の測定値を比較する場合とで異なる。

利用者や機器は、記録にイベントやラベルを付けられる。実験の段階や条件を階層的に整理することも候補とする。アプリが見つけた通信、変化、測定結果も調査の手掛かりになる。利用者は手掛かりから関連する区間へ移動し、複数の記録を見比べ、解釈の根拠となった元のデータを確認できる。必要に応じて長い記録の一部を取り出して個別に分析し、連続した変化を調べるときは全体を分析できる。

分析の中心となる機能は、対話的な GUI と自動化に使う CLI の双方から利用できることを目指す。操作方法ごとの機能や体験が完全に一致する必要はない。表示部分を替えても分析の仕組みを利用し続けられることが望ましい。GUI では長さや種類の異なる記録を扱いやすく見渡せる体験を目指す。

この体験を具体化する場面は [ユースケース](use-cases.ja.md) に記す。

## 対象となる範囲の候補

- デジタル信号、アナログ波形、低頻度の測定値、文字列、イベントなどの取り込みと表示
- 異なる取得元や形式からの入力、分析、後続の分析へ渡せる形での出力
- 分析結果を別の分析の入力として利用すること
- 速い変化と遅い変化を含む、幅広い時間スケールの記録と分析
- ライブ取得と、既存ファイル・過去の記録の分析
- 複数の記録を一つの調査や実験の中で扱うこと
- 記録へのラベル付け、区間の整理、イベント単位での移動
- 長い記録からの区間の切り出しと、元の記録全体の分析
- データの特徴や構造の発見、複数の解釈候補の提示、利用者による補正
- ノイズを考慮した共通の前処理と、途中で性質が変わる区間の発見
- 送受方向を含む通信内容の時系列と、未解釈の区間や変化点の提示
- 解析機能を改善した後の、同じ記録に対する再分析
- 解釈された結果から元の記録とその前後へたどること
- 長時間の記録から注目すべき区間を見つけ、後で見直すこと
- 新しい取得元、形式、分析方法を容易に追加できること
- GUI と CLI など、複数の操作方法から共通の分析機能を利用すること

入力・分析・再利用可能な出力を核とし、それ以外は範囲を議論するための候補とする。すべてを最初の版に含めるという意味ではない。実験の手順を決めて進行させることは製品の中心に置かない。計測器からの取得に必要な操作と、実験自体の制御との境界は今後整理する。

## 目指す性質

- **異種の記録を結び付けられる:** 一種類の波形や一台の機器だけで調査が閉じない。
- **精度を用途に合わせられる:** 時間精度が異なる記録も共通の分析の枠組みで扱い、すべてのデータ源に同じ精度を要求しない。
- **利用者が判断に参加できる:** 自動分析の結果を確定事項として押し付けず、条件指定や修正を受け付ける。
- **分析の根拠をたどれる:** 高次のイベントや集計から、元の記録と分析条件へ戻れる。
- **結果を再利用できる:** 分析結果を画面表示だけで終わらせず、後続の分析や外部利用へ渡せる。
- **必要な粒度で取り出せる:** 後工程に必要なコマンド、応答、特徴、区間を選んで取り出し、必要なら元の記録へ戻れる。AI に渡す場合も、目的に関係する情報から調べ始められる。
- **未知を残せる:** 解釈できない信号を黙って捨てず、後から再分析する対象として示せる。
- **後から広げられる:** 新しい取得元や分析方法を組み合わせられる。
- **再利用できる:** 記録と分析の文脈を保存し、後から見直せる。
- **操作方法から独立している:** 分析の仕組みを特定の GUI に閉じ込めず、別の操作方法や表示にも利用できる。

## 非目標の候補

以下は、現時点でプロジェクトの中心的な成功条件には置かない候補である。採否は今後検討する。

- 特定のロジックアナライザや計測器だけに対応する専用ビューアを完成させること
- すべてのプロトコルや異常を、利用者の知識なしで必ず正しく自動判定すること
- すべてのデータ源を常にサンプル単位で厳密に同期させること
- 一種類のファイル形式をすべての機器や用途へ強制すること
- 汎用的な実験自動化環境やノートブック環境を製品の中心に据えること

## 成功した状態の例

まず、何らかのデータを入力して、用途に合う粒度の分析結果を出力し、その結果を独自スクリプトなどの後工程へ渡せることを中心的な成功条件とする。既知の通信では送受方向とコマンド・応答の時系列を得られ、未解釈の箇所や通信条件の変化も見つけられることを目指す。GUI と CLI のどちらから利用しても、分析結果と元のデータの関係を追えるようにする。

次の二つの場面で、利用者が元データ、共通の分析結果、後工程での判断を無理なく行き来できることも、成功を考えるための具体例とする。

1. ロジックアナライザの記録で通信の候補を見つけ、復号内容とアナログ波形の変化を照合し、気になるイベントから元の波形へ戻れる。
2. 自動計測で得た設定、電圧・電流・温度の値、試験マーカーを一緒に記録し、試験段階ごとの結果を後から比較できる。

長回しした記録から、マーカーで区切られた独立の実験を取り出せる一方、連続的な変化は記録全体として調べられることも成功を考える例とする。

これらに加え、利用したい機器や独自の分析方法を、過度な手間なく追加できる状態を目指す。達成水準や優先順位は未定である。
