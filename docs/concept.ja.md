# WireSkein の目的と範囲

[English](concept.md)

## 目指すもの

WireSkein は、ロジックアナライザなどの観測記録から、問いに要る情報を取り出して後工程（試験の合否判定、スクリプト、人、AI）へ渡すための道具です。波形を人が画面で眺めて終わりにせず、「期待どおりか」をコードで照合し、「何が流れたか」を構造化したデータとして出します。

## 解決したい課題

| 課題 | WireSkein の方針 |
| --- | --- |
| **機材とライセンスに縛られる。** 使いやすいアプリほど専用機材が前提で、手元のロジアナや自作プローブと組み合わせにくい。拡張に本体のビルドが要る、ライセンスが組み込みに合わない | 取得元を選ばない（sigrok の `.sr`、VCD、sigrok 対応機器、OEP のプローブ）。MIT ライセンス。方式やデバイスは TOML を足すだけで増やせる |
| **テストにならない。** キャプチャを期待と照らし合わせて OK / NG を出す口がない | 試験の中で期待をコードとして書き、`wireskein verify` が測定値付きで照合する（[記録の形式](run-format.ja.md)、[キャプチャで試験する](capture-test-guide.ja.md)） |
| **情報が多すぎる一方、大事なものを落とす。** 全波形を毎回読むのは重い。要約の途中で、途中から速くなった通信をノイズとして捨てた例がある | 必要な層・区間・項目だけを出す。未解釈の区間、候補ごとの根拠、取得の品質は隠さない |
| **出力を使うたびに加工が要る。** 表示用の文字列を読み直し、ツールごとに変換スクリプトを書いている | 出力は安定した構造の JSON。時刻は刻みの整数で、元のキャプチャへ戻れる |
| **記録の種類ごとに分断される。** ロジック、アナログ、別の機器の記録を、別の道具で見て時刻を手で合わせる | ロジックとアナログを 1 つのファイルに持ち、同じ信号のエッジから時刻を合わせる（[ファイル形式](wireskein-format.ja.md)） |

## 大切にする性質

- **未解釈を解釈済みとして扱わない。** 読めた部分と読めていない部分、検査した項目と検査できなかった項目を区別して返す。照合で検査できなかったものは、既定で失敗にする。
- **元データを書き換えない。** 合わせ込みや注釈は別の項目として足し、取ったサンプルと記録した時刻はそのまま残す。取っていないサンプルを作らない（間引いたチャンネルを水増ししない）。
- **CLI と JSON が基本。** 画面がなくてもすべての機能を使える。GUI（ビューア）は同じファイルと結果を表示する。
- **呼び出す側が対象と処理を決める。** 自動判定も、呼び出す側が選んで実行する処理の一つ。試験の進行と合否の判断は、外部の試験環境が担う。

## 範囲に入れないもの

- 実験全体を制御する環境や、汎用のノートブック。
- あらゆる未知の信号を必ず正しく判定する仕組み。推定は候補と根拠を返し、確かでないものは確かでないと示す。
