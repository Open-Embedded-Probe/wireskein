## 観測結果

### I²C: 元データと保存結果の再現

4組すべて 8 MHz の `.sr` から、合計227件の取引を再構成でき、保存済み `.jsonl` と**バイト単位で一致**した。結果の内容ハッシュも、各ファイル名の末尾と一致した。UART マーカーから `CASE_BEGIN`、`CASE_END`、`PHASE` などを読み、取引に `operation` と `phase` を付けるところまで再現した。SHT30 では54件と57件、QMP6988 では各58件の取引が得られた。各組に1件ずつ、元 `.sr` と結果 `.jsonl` の両方を参照する observation YAML がある。

具体例として、SHT30 の結果では `Reset` 区間にアドレス `0x44` への書き込み `0x30 0xA2` が取引として残る。元 `.sr` には I²C と UART の信号が同じ時間軸で入り、`operation` / `phase` は UART の実マーカーから導かれる。外部試験の結果や CRC 判定などは observation YAML のイベントにも保存されており、取引列だけで実験の意味を完結させていない。

4組の `.sr` は合計118,070バイト、保存結果は61,064バイトだった。`.sr` 内のロジックデータは合計約39 MB だが、セッションファイル上では強く圧縮されている。この標本では、意味のある取引列への整理は有用でも、JSONL が圧縮済みの元記録に対して極端に小さいとは言えない。

一方、保存結果の各取引の `start_offset_us` は最初の I²C START を0とする相対位置であり、元波形上の位置は記録されていない。例えば1組目の最初の START は元キャプチャの983,172.625 µsにあるが、保存結果の最初の取引は0 µsで始まる。元波形へ直接ジャンプしたり、その区間だけをエビデンスとして切り出したりするには、**キャプチャ上の時刻またはサンプル範囲への対応**を別に残す必要がある。現状でも全体を再デコードすれば対応を再計算できる。

### RVSWD: 未解釈区間と取得条件

| 記録 | サンプルレート | フレーム | 未解釈 | 短いフレームのパリティ失敗 | メモリアクセス |
| --- | ---: | ---: | ---: | ---: | ---: |
| `l103/target_info.sr` | 50 MHz | 334 | 0 | 0 | 40 |
| `v203/target_info.sr` | 50 MHz | 328 | 18 | 0 | 34 |
| `v203-100mhz/target_info.sr` | 100 MHz | 328 | 0 | 0 | 38 |

L103 の40件のメモリアクセスは保存済み `target_info.mem.txt` と、操作種別・アドレス・値の列が一致した。例えば元波形からフレームを読み、`MEMR 1ffff704 = 10310710` というレジスタの読み出しまで進められる。同じ操作の `.ndjson` には USB 側の転送、`.json` には取得条件がある。V203 の50 MHz記録には、保存済みの `.mem.txt` にメモリアクセスがなく、今回使った解析器では34件を得た。既存の保存結果と解析器の版・方式の違いが、後工程に渡せる情報量を変える例である。

V203 の50 MHz記録では、未解釈フレームの例が61.99854 ms、124.77802 ms付近にあり、元波形のサンプル範囲も取得できた。未解釈の18件を消さずに、認識できたフレームやメモリアクセスと併記できる。100 MHz は別回の取得であり、フィルターも50 MHzの3サンプル保持に対してビットクロック1サンプル・フレーム境界3サンプル保持を用いた。今回の差だけでサンプルレート単独の効果は断定できない。

### I²C: 元波形への対応と区間エビデンス

追加の `section_probe.py` では、元 `.sr` のサンプルを読み、解析器が示す取引開始・終了の時刻をサンプル番号へ変換した。4記録の**取引開始227件すべて**で、SCL が HIGH の間に SDA が HIGH→LOW へ変化する位置と一致した。STOP のある**173件すべて**でも SDA の LOW→HIGH と一致した。この範囲では、結果にサンプル範囲を付けて元波形へ直接戻せる。繰り返し START で終わる取引は STOP として数えていない。

実 UART マーカーの `CASE_BEGIN` / `CASE_END` を親区間、`PHASE` を子区間と仮に読み替えた。4記録から親26区間、子18区間を作れ、マーカー境界をまたぐ取引はなかった。同じ親の下で `Single Measurement` が6回現れる SHT30 記録では、`Single Measurement#1`〜`#6` として別々に選べた。例えば1組目の `#1` は29取引、`#2` は3取引で、記録全体は54取引である。これは既存マーカーによる実験であり、製品のマーカー記法を決定するものではない。

親26区間すべてについて、元 `.sr` の**連続したサンプル範囲**を一時的な `.sr` に切り出し、再度デコードした。選んだ取引の全フィールドと相対時間情報が26件すべて一致した。SHT30 の6区間では、元波形から再計算するクロックストレッチ情報も一致した。区間開始の200 µs前から切り出したのは、UART のマーカー先頭を読める状態にするためである。100 µs前からの切り出しではマーカー先頭が欠け、取引の文脈が失われる例を確認した。**200 µs は今回の記録で通った値**であり、一般の取得元や解析器に必要な前置範囲ではない。

子の `PHASE` 区間だけを切り出す試行では、4例とも取引自体は読めたが、親 `CASE_BEGIN` が区間外のため `operation` が空になった。切り出し時に把握していた親の名前を文脈情報として添えると、相対時間とクロックストレッチを含む結果が4例すべて一致した。子区間のエビデンスは、波形だけでなく**区間開始時のマーカー文脈**が必要な場合がある。前段の復号器の内部状態まで必要になる場合は今回確認していない。

## この段階で分かったことと限界

- **再現性:** I²C の4組は、同じ元記録と同じ解析処理から保存結果を完全に再生成できた。これは解析内容の意味的な正しさを独立に証明するものではない。既知の送受内容や別の観測との照合は次に行う。
- **来歴:** 取引・コマンドのような軽い結果にも、元ソース、区間、解析条件、解析機能、未解釈部分への参照を付ける価値がある。I²C の現行結果はキャプチャ開始からの位置を直接持たず、WCH の既存テキスト結果もサンプル範囲までは保持していない。
- **複数の観測:** WCH の USB 転送ログと線上波形は同じ操作名で対応付くが、共通マーカーによる厳密な時刻同期はない。操作順や内容の一致は手掛かりになっても、転送と線上フレームが一対一に対応するとは限らない。
- **未検証の範囲:** この2組の資料は主にデジタル通信であり、アナログ波形、低頻度測定、異なる取得元の時刻合わせ、階層マーカーの区間選択はまだ検証していない。I²C 側には実物の実験マーカーがあるが、現在の `CASE` / `PHASE` 表現は企画文書の見出し階層そのものではない。

WCH の既知パターン、フィルター、概況出力、時刻合わせの生成試験、保存方式の小規模試験は [追加検証](extended-findings.ja.md) にまとめる。

マーカーの役割、プロトコル復号前の信号特徴、クロック統計、候補を連鎖させる順序、最初の処理プリセット候補は [基礎分析の検証](foundations.ja.md) にまとめる。

匿名の線から基本プロトコル候補を列挙し、ビット／取引から上位解析へ進めた試行、線上の独立監査、警告と未評価の扱い、仕様判断に必要な追加資料は [ワークフロー調査](workflow-findings.ja.md) にまとめる。
