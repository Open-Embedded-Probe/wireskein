# 基礎分析の検証: マーカー、信号の特徴、解析候補

2026-09-27。これは製品の仕様や自動分類器の精度評価ではない。既存の4件の I²C/UART 同時記録、RVSWD、SWIO の実記録を使い、プロトコル名を付ける前に何が観測できるかを調べた。SPI だけは対象に実記録がないため、2転送の生成波形で特徴量の取り方を確かめた。元ファイルは読み取りのみで使用した。

## 再実行

[初回調査](README.ja.md) と同じ `uv` 環境と `sigrok-cli` を用意し、リポジトリのルートで実行する。結果 JSON は再生成できるため Git から除外する。

~~~sh
uv run --project experiments/initial-feasibility python experiments/initial-feasibility/foundation_probe.py > experiments/initial-feasibility/foundation-result.json
~~~

## マーカーは区間と情報を分けて扱う

4件の実記録には、別チャンネルの UART から取り出した112件のマーカーがあった。既存解析器のキーワードをそのまま使い、内容は次のように分類できた。

| 実際の種類 | 件数 | この記録での役割 | 例 |
| --- | ---: | --- | --- |
| `CASE_BEGIN` / `CASE_END` | 各26 | 試験の親区間を開く／閉じる | `Device Detection` |
| `PHASE` | 18 | 親の中の段階を切り替える | `polling-high` |
| `INPUT` | 20 | 与えた操作・条件を記録する時点のイベント | `{"command":"0x30A2"}` |
| `RESULT` | 22 | 外部試験が知っている結果を記録する時点のイベント | `{"status":"captured"}` |

`INPUT` と `RESULT` の内容はこの標本ではすべて JSON オブジェクトとして読めた。これらを見出しと同じ区間として解釈すると、条件や外部判定を誤って分析対象の境界にしてしまう。子の `PHASE` を選んでも親の試験名が必要になる例は[区間エビデンスの実験](README.ja.md)で確認した。

企画上のマーカーには、少なくとも次の**別々の軸**がある。名称や保存形式はまだ決めない。

| 軸 | 区別したいもの | 理由 |
| --- | --- | --- |
| 由来 | 取得時の機器・外部試験、利用者の注記、分析が見つけたイベント | 外部の試験結果と推定結果を混同しない |
| 役割 | 区間の開始・終了、段階、設定条件、測定値、外部判定、異常の手掛かり | 区間選択に使うものと、その区間に付く情報を分ける |
| 時間上の形 | 一点の出来事、範囲、範囲全体に適用する条件 | 境界の前後や測定値の所属を再確認できる |
| 階層 | 親の試験、その中の条件、その中の操作 | 親全体と子だけの両方を対象にできる |

既存の `CASE` / `PHASE` は企画した Markdown 風の見出し記法そのものではない。今回確かめたのは**役割の分離と実区間の選択**であり、記法、壊れた階層、複数ソース間の衝突規則は未検証である。元の文字列、取得元と位置、割り当てた階層を区別して残す方向が妥当と考える。

## プロトコル名を付ける前の観測

| 観測 | 実データで得たもの | 解釈の限界 |
| --- | --- | --- |
| 活動線と無変化線 | I²Cの4記録は各8線のうち UART_TX・SCL・SDA の3線が変化、5線が無変化。RVSWD は2線、SWIO は1線が活動 | 無変化線は電源・GND・未接続などをこれだけでは区別できない |
| UART らしい時間単位 | UART_TX の1ビット幅に相当する短い HIGH / LOW は、8 MHz 標本でおおむね69〜70サンプル。これは約115.2 kbit/s に相当 | 幅の整数倍だけでは UART と確定しない |
| 独立したクロック候補 | I²C の SCL は連続した立ち上がりの大半が80サンプル間隔で約100 kHz。4記録で安定区間の中央値と5〜95パーセンタイルは80サンプル | 全体には待ち時間とクロックストレッチがあり、周期が常に80とは言えない |
| 線同士の関係 | SDA の変化のうち SCL が HIGH の時点にある割合は QMP6988 で約9%、SHT30 で約14%。生成した SPI では MOSI 変化14件がすべてクロック LOW、全16立ち上がりが CS 有効中 | DATA がクロック LOW で変わる性質だけでは I²C / SPI / SWD を分けられない。SPI の数値は生成値 |
| 複数速度・短いパルス | RVSWD のクロック立ち上がり間隔には複数の山があり、100 MHz 記録で3サンプル以下の短いランが5,771件。別の[追加検証](extended-findings.ja.md)では高速区間を特定した | 全体の中央値をジッターや代表周波数と呼ぶと、速度変更や短い反射を隠す |
| 1線のパルス列 | SWIO には活動線が1本で、短い間隔と長い空きが混在 | 1線というだけで SWIO、UART、IR などを判定できない |

**誤判定の実例:** 簡易的に「LOW の開始と、10ビット後の HIGH」を UART 8N1 の形として数えると、UART_TX では候補開始の約72%が合った。一方で、**SCL では94〜99%が合ってしまった**。周期的なクロックを `0101…` と読むだけで見かけ上の開始・停止ビットが作れるためである。SCL 側は候補バイトの大半が `0x55` になった。したがって、ビット幅と短いフレーム形だけを候補の一致率として出すのは危険である。独立した線との関係、バイト列の偏り、実際の上位文法、期待される応答との整合を重ねて確認する必要がある。この簡易試行自体は正式な UART 復号器ではない。

### クロック、ジッター、取得精度

I²C の4記録で、SCL の80サンプル前後の立ち上がり間隔を選ぶと、中央値・5〜95パーセンタイルは80・80〜80サンプルだった。8 MHz の1サンプルは0.125 µsである。これは**記録上の安定区間**を示すが、実信号のジッターがゼロという意味ではない。量子化より細かい揺らぎは見えず、選択範囲外の長い間隔も意図的に別扱いにしている。

UART_TX の短い1ビット相当のランは5〜95パーセンタイルで69〜70サンプルだった。1ビットの理想値は8 MHz / 115,200 = 約69.44サンプルなので、69と70への丸めをそのままジッターと呼べない。ジッターを評価するなら、まず連続した同一速度の区間と基準クロックを決め、取得サンプル間隔による誤差を分けて、残差の分布・極値・時間変化を出すべきである。RVSWD の速度が変わる区間には一つの基準周期を当てない。

## 候補の連鎖は段階ごとに検証する

次の連鎖は、今回の実記録から確認できた経路と、次に試すべき経路を区別したもの。各段階の結果は元ソースの位置へ戻れるようにし、途中の未解釈部分を保持する。

| 前段で得るもの | 試す下位の解釈 | 上位へ渡すものと実例 | 状態 |
| --- | --- | --- | --- |
| 1線のビット時間候補 | UART の速度・極性・フレーム形式 | バイト列から UART マーカー文法へ。今回の112マーカーを取り出せた | 実記録で確認。UART の候補自動選択は未検証 |
| クロック＋データの関係 | I²C の START / STOP、アドレス、ACK、データ | 227取引から SHT30 の測定値・CRC へ | 実記録で確認 |
| クロック＋双方向データ | RVSWD のフレーム境界・ビット・パリティ | DMI / メモリアクセスから chip ID へ | 実記録で確認。未解釈とパリティ不一致あり |
| 1線のパルス群 | SWIO のフレーム形式 | 書き込み・読み戻しの値へ | 実記録で確認。多くの群の意味は未検証 |
| クロック＋選択線＋データ線 | SPI のモード・ビット順・転送境界 | バイト列から機器固有コマンドへ | 生成波形の特徴のみ。実記録で未検証 |
| UART / SPI / I²C 等の正しく得たバイト列 | SCPI、Modbus、機器固有形式などの文法 | コマンド、応答、未知フィールドへ | 今回の標本では自動候補選択を未検証 |

候補を表示するなら、少なくとも**どの線・区間・速度を仮定したか、フレームのどれだけを説明できたか、検査失敗がどこにあるか、未解釈がどれだけ残るか**を別々に示したい。例えば RVSWD ではフレームの長さが既知でもパリティ失敗があり、上位の既知データと一致した部分があっても全区間の正常性は保証されない。候補の単一スコアや具体的な探索順は、誤判定例と未知方式の正解付き資料を増やしてから定める。

## 最初に用意したい処理プリセットの候補

これは今回の作業で繰り返し必要になった**処理の組み合わせ案**であり、実装範囲の決定ではない。対象ソースやマーカー区間を替えて同じ処理を再実行できる形を想定する。

| 候補 | 入力から出すもの | 初期状態の考え方 |
| --- | --- | --- |
| ソース概況 | チャンネル、取得レート、活動・無変化、欠落、長さ、マーカー候補 | 元データの品質と分析可能範囲を先に知らせる |
| 信号の指紋 | エッジとラン幅、活動区間、クロック候補、線間の変化、搬送波や速度変化の候補 | 根拠の区間を添え、未知のまま残せる |
| 時間・品質 | 区間別の周期、デューティ比、基準からのずれ、外れ値、サンプル精度 | 速度変更とジッターを分けて表示する |
| マーカー整理 | 文字列復号、見出し／条件／外部結果の分類、階層と元位置 | 区間を開くものと時点のイベントを混同しない |
| 候補検証 | UART / I²C / SPI / SWD などの条件別試行、整合・不一致・未解釈の位置 | 一致率だけで自動確定しない |
| 詳細解析とエビデンス | 選んだ連鎖の詳細、簡易一覧、例外一覧、実データの切り出し | 同じ条件から再実行できるようにする |
| 記録間比較 | 同じ処理で得た出力の項目選択と差分 | 時刻や可変値を伏せたことを明示する |

フィルターも最初から万能な一括設定にせず、用途と位置を区別して試す。

| フィルター候補 | 使う理由 | 確認が必要な点 |
| --- | --- | --- |
| 短パルス除去・ノイズゲート | 反射やスパイクの影響を抑える | 実際の高速信号を失う例がある。初期状態は無効が妥当 |
| チャタリングのまとめ | 操作イベントとしてのボタンを読む | 物理的なチャタリング調査では適用しない |
| 搬送波から包絡を取り出す | IR などの長短の符号を見やすくする | 元の搬送波と変調の両方へ戻れるようにする |
| アナログの閾値・ヒステリシス・平滑化 | アナログ波形からデジタル候補や傾向を得る | 実測アナログがなく、閾値の選択と誤差は未検証 |
| 時刻補正・再サンプリング | 別取得元の比較や表示 | 元時刻・補正値・不確かさを残す |
| 復号後の項目選択・集計 | コマンドだけ、差分だけ、例外だけを出す | 入力波形を変えたフィルターと区別し、省いた範囲を示す |

処理の順序を固定する前に、フィルター前後の差と除外位置を同時に出せるかを確かめる。[追加検証](extended-findings.ja.md)では、同じ RVSWD 波形でも保持条件で未解釈数が変わり、短い成分を一律にノイズとして消せないことを確認している。

## 次に必要な標本

- **実測 SPI、IR、アナログ、低速測定値:** 特徴候補とプリセットの適用範囲を確かめる。生成 SPI の結果を実機の認識率とは扱わない。
- **未知方式と誤配線の正解付き記録:** 候補の順位と棄却理由、UART に見えるクロックのような誤判定を測る。
- **基準時刻が分かる取得:** サンプル量子化、発信源のジッター、取得器の誤差、ドリフトを分離する。
- **段階的に壊したマーカー・通信:** 欠けた終了、重複名、破損バイト、途中開始、速度変更、CRC失敗時の表示とエビデンスを試す。

今回のデータで支持されたのは、信号の基礎統計とマーカー整理を、プロトコルの確定や上位解釈より前に置く必要性である。自動分類の閾値、共通スコア、標準フィルターの既定値はまだ決めない。
